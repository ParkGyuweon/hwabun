# 3. 데이터베이스 덤프

EC2-1의 `ec2-1-mysql-1`에서 2026-09-23 02:29:03부터 02:29:10 UTC(11:29 KST)에 추출한 데이터 포함 스냅샷입니다. MySQL 클라이언트 버전은 `8.4.11`, 서버 이미지는 `mysql:8.4`입니다. `shop_backend`와 `dw`를 각각 `--single-transaction --quick`으로 추출했으므로 각 파일 안의 InnoDB 테이블은 해당 추출 시점의 스냅샷입니다. 두 DB 파일을 하나의 전역 트랜잭션으로 묶은 것은 아닙니다.

| DB | 덤프 파일 | 확인된 테이블 수 | 압축 크기 | SHA-256 |
| --- | --- | ---: | ---: | --- |
| 쇼핑몰 원장 | `db/shop_backend_20260923T022903Z.sql.gz` | 38 | 1,384,483 bytes | `54a0931918e0068defde510b6304f77ba0c7ddd1c7877c8470e8d8ec3c930c68` |
| 분석 마트 | `db/dw_20260923T022903Z.sql.gz` | 22 | 14,132,045 bytes | `1c547fdddcde5d46a454feeba3bc53e8c041a20bd74c9583f2a5e4902dc4caec` |

두 파일은 로컬 복사 후 SHA-256 대조와 gzip 전체 스트림 해제 검증을 통과했습니다. 별도의 빈 MySQL에 복원하는 통합 테스트는 수행하지 않았습니다. 추출 당시 EC2-2에서 Q2부터 Q4 배치가 진행 중이었고, **이 덤프는 그 배치의 새 Mart가 MySQL에 발행되기 전 상태**입니다. 시연 직전 최신 Mart까지 제출해야 한다면 해당 배치가 끝난 뒤 `dw` 덤프를 다시 생성해야 합니다. 실행 중인 배치를 중단하거나 DW를 임의로 비우지 마세요.

## 보안과 포함 범위

- 두 파일은 테이블 구조와 데이터를 포함합니다. `shop_backend`에는 회원 정보와 비밀번호 해시, 주문 정보가 들어갈 수 있습니다. `dw`에도 사용자별 분석 값이 들어갈 수 있습니다. 두 압축 덤프는 이 GitLab 저장소에 포함되므로 저장소와 MR의 접근 권한을 허가된 평가자로 제한하고 공개 저장소로 전환하지 마세요.
- `db/*.sql.gz` 두 파일은 Git 추적 대상이며 GitLab 소스 클론 시 함께 내려옵니다. 압축하지 않은 `db/*.sql` 파일만 `.gitignore`로 제외합니다.
- MySQL 서버의 `root`, `shop_backend`, `dw_reader`, `dw_writer` 계정과 GRANT는 `mysqldump --databases`에 들어가지 않습니다. 복원 서버에서 환경별 비밀번호를 새로 정하고 최소 권한으로 발급해야 합니다. 비밀번호 값이나 EC2 `.env`는 덤프와 함께 제공하지 않습니다.
- `shop_backend/mysql-erd.sql`, `shop_backend/seed/shop_backend_seed.sql`, `contracts/dw/schema.sql`은 빈 DB 구축용 소스이며 이 데이터 포함 덤프와 다릅니다. 이미 덤프를 복원한 DB에 시드를 중복 적용하지 마세요.

## 무결성 확인

압축 파일을 전달받은 Linux 호스트에서 확인합니다.

```bash
cd S15P21A306/exec
sha256sum db/shop_backend_20260923T022903Z.sql.gz db/dw_20260923T022903Z.sql.gz
gzip -t db/shop_backend_20260923T022903Z.sql.gz
gzip -t db/dw_20260923T022903Z.sql.gz
```

## 복원: 빈 테스트용 MySQL에만 수행

아래 명령은 동일 이름의 DB와 테이블을 교체할 수 있습니다. **운영 DB에 바로 실행하지 마세요.** 별도 테스트 MySQL 또는 새 빈 Volume을 준비하고, 그 서버의 root 비밀번호와 접근 권한을 확인한 뒤 실행합니다. 덤프는 `--databases`로 만들어져 DB 생성문을 포함합니다.

```bash
cd S15P21A306/exec
gzip -dc db/shop_backend_20260923T022903Z.sql.gz | \
  sudo docker exec -i <빈 MySQL 컨테이너 이름> sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot'
gzip -dc db/dw_20260923T022903Z.sql.gz | \
  sudo docker exec -i <빈 MySQL 컨테이너 이름> sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot'
```

복원 뒤 `shop_backend`와 `dw`의 테이블 수, Shop Backend 로그인, 판매자 Dashboard API, 추천 서버의 DW 조회를 확인합니다. MySQL 계정과 외부 서비스 키는 [포팅 매뉴얼](1_포팅_매뉴얼.md#3-환경-변수와-설정-파일)과 [외부 서비스 안내](2_외부_서비스_정보.md)에 따라 별도로 설정합니다. 실제 데이터의 외부 반출 및 보관 기간은 팀의 제출 정책을 따르세요.
