# 2. 외부 서비스 정보

가입과 권한 발급은 서비스 운영자가 수행합니다. 아래에는 공개 가능한 절차와 프로젝트에서 소비하는 설정 이름만 적고 실제 키, 비밀번호, SSH 개인키는 싣지 않습니다. 소셜 로그인과 포톤 클라우드, 코드 컴파일 API는 현재 HWABUN 소스의 필수 외부 서비스가 아닙니다. 쇼핑몰 로그인은 Shop Backend 계정 기반입니다.

| 서비스 | 사용 목적 | 준비할 것 | 설정 위치 |
| --- | --- | --- | --- |
| SSAFY GitLab | 저장소 클론과 Jenkins 소스 | 프로젝트 접근 권한이 있는 계정 또는 배포용 토큰 | Git credential 또는 Jenkins credential. 저장소 파일에 토큰 저장 금지 |
| AWS EC2, DNS | EC2-1 웹과 MySQL, EC2-2 Kafka와 Spark | 서버 2대, SSH 키, 도메인 DNS, 역할별 보안 그룹 | AWS 콘솔과 두 서버의 `deploy/ec2-*/.env` |
| Let's Encrypt | EC2-1 HTTPS 인증서 | 실제 도메인과 인증서 알림 이메일, 80 포트 검증 | EC2-1 호스트 `/etc/letsencrypt`, `CERTBOT_WEBROOT_PATH`, Nginx 설정 |
| PortOne V2 및 카카오페이 테스트 채널 | 사람의 주문 결제창과 서버 결제 검증 | PortOne 상점, 테스트 결제 채널, Store ID, Channel Key, V2 API Secret | EC2-1 `.env`의 `VITE_PORTONE_*`, `PORTONE_API_SECRET` |
| SSAFY GMS | AI 처방 문장, 피드백 분류, 선택적 에이전트 실행 | SSAFY에서 발급한 GMS 키와 사용 한도 | EC2-1 `.env`의 `GMS_KEY`, 에이전트 실행 PC의 루트 `.env` |
| OpenAI API | 에이전트 러너의 `--openai` 선택 실행 | 개인 API 키와 과금 계정 | 로컬 루트 `.env`의 `OPENAI_API_KEY`. 기본 배포에는 불필요 |

## GitLab과 AWS

GitLab 프로젝트 읽기 권한을 받아 `git clone`합니다. Jenkins는 별도 credential로 GitLab에 접근하도록 구성합니다. 개인 액세스 토큰을 URL이나 `.env.example`에 넣지 마세요. 두 EC2에 Docker Engine과 Compose v2를 설치하고 EC2-1 도메인을 연결합니다. EC2-1 보안 그룹은 HTTP 80과 HTTPS 443, 관리자 출발지의 SSH 22를 허용합니다. 사설망에서만 EC2-1 → EC2-2 Kafka 9092와 Spark UI 18080, EC2-2 → EC2-1 MySQL 13306을 허용합니다. AWS의 [보안 그룹 규칙 예시](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/security-group-rules-reference.html)에 따라 출처를 최소화합니다. EC2-2 Kafka는 현재 인증 없는 PLAINTEXT이므로 9092를 전체 인터넷에 열지 않습니다.

## Let's Encrypt

별도 유료 계정은 필요 없지만 도메인 소유 및 접근 가능한 이메일이 필요합니다. EC2-1의 Certbot이 `j15a306.p.ssafy.io` 인증서를 발급하고, Nginx가 인증서 경로를 읽기 전용으로 마운트합니다. 최초에는 Nginx가 80을 점유하기 전에 standalone 검증을 하고, 이후 webroot 갱신 설정과 `renew --dry-run`을 점검합니다. 상세 명령은 [포팅 매뉴얼](1_포팅_매뉴얼.md#23-ec2-1-mysql-인증서-웹-서비스)을 따릅니다. 공식 [Let's Encrypt 시작 안내](https://letsencrypt.org/getting-started/)도 참고하세요.

## PortOne V2와 카카오페이

1. [PortOne 관리자 콘솔 안내](https://developers.portone.io/opi/ko/console/guide/channel-manage)에 따라 상점을 만들고 Store ID를 확인합니다.
2. 콘솔에서 카카오페이 테스트 채널을 연결한 뒤 Channel Key를 받습니다. 결제 수단은 `EASY_PAY`, 통화는 KRW입니다. 실제 결제 채널 대신 테스트 채널인지 반드시 확인합니다. [카카오페이 V2 연동 안내](https://developers.portone.io/opi/ko/integration/pg/v2/kakaopay?v=v2)를 참고하세요.
3. 콘솔의 V2 API Secret을 발급받습니다. 이 값은 브라우저 공개 키가 아니라 서버가 결제 내용을 다시 조회하기 위한 비밀값입니다. [V2 API 문서](https://developers.portone.io/api/rest-v2)를 참고하세요.
4. EC2-1 `deploy/ec2-1/.env`에 `VITE_PORTONE_STORE_ID`, `VITE_PORTONE_CHANNEL_KEY`, `PORTONE_API_SECRET`, `PORTONE_API_URL=https://api.portone.io`를 설정합니다. 앞의 두 값은 Nginx의 Vite 빌드 인자로 정적 번들에 들어가므로 Nginx 이미지를 다시 빌드합니다. API Secret은 Shop Backend 컨테이너에만 전달합니다.
5. 소비자가 결제하면 프론트가 `@portone/browser-sdk`로 결제창을 띄우고, Shop Backend가 PortOne REST API에서 결제 상태와 금액을 조회한 뒤 주문을 확정합니다. 결제창 응답만으로 PAID 처리하지 않습니다.

결제 키가 없을 때의 테스트 주문 경로는 실제 카카오페이 검증이 아닙니다. 배포의 `TEST_PAY_ALLOWED_MEMBER_PREFIX=PA`는 에이전트 계정에만 테스트 결제를 허용하기 위한 값이므로 공개 회원 계정으로 우회하지 마세요.

## SSAFY GMS와 선택적 OpenAI API

GMS는 SSAFY가 키를 발급하는 내부 서비스입니다. 공개 가입 링크나 자동 발급 절차를 임의로 기재하지 않습니다. 팀의 SSAFY 관리 경로에서 키와 호출 한도를 전달받아 EC2-1 추천 컨테이너에만 `GMS_KEY`로 설정합니다. 추천 기본 응답과 Kafka 처리에는 키가 필수가 아니지만, AI 처방 문장과 피드백 분류는 키가 없으면 제한됩니다. 에이전트 런처를 로컬에서 실행한다면 로컬 루트 `.env`에도 별도로 설정합니다. 호출량에 따라 크레딧이 소모되므로 시연 범위와 `PRESCRIPTION_LLM` 설정을 확인하세요.

`simulator/agents/agent_runner.py --openai` 옵션만 개인 OpenAI API 키를 사용합니다. 기본 GMS 경로 또는 일반 웹 서비스 배포에는 `OPENAI_API_KEY`가 필요하지 않습니다. OpenAI API를 선택한다면 [공식 API 플랫폼](https://platform.openai.com/)에서 별도 키를 발급받고 로컬 비밀 파일로 관리합니다.

## 외부 서비스가 아닌 자체 운영 구성

Kafka, Spark, MySQL, Prometheus, Grafana는 각 EC2의 컨테이너로 운영합니다. Grafana 계정은 외부 가입 계정이 아니라 EC2-1 `.env`의 `GRAFANA_ADMIN_USER/PASSWORD`로 초기화되는 자체 계정입니다. Stripe, 소셜 OAuth, Photon Cloud 계정은 현재 빌드 및 시연에 필요하지 않습니다.
