처리 순서

  1. body와 상품명을 프롬프트에 넣고 어휘 목록에서 딱 하나 고르게 한다. 건당 호출 1회.
  2. 답의 축·카테고리가 목록에 글자 그대로 있는지 검사. 하나라도 어긋나면 other.
  3. 응답 JSON은 첫 객체만 떼어 낸다. 3회 실패하면 other.
  4. 금지어 대조 (LLM 없음). NFC·소문자·한글/자모/영문/숫자만 남겨 정규화한 뒤 부분 일치. "시 발"·"시.발"도 잡힌다. 출처 VaneProject/bad-word-filtering (MIT) 599개. 보태는 단어는 added, 오탐 예외는 allow("똥손"), 끄는 단어는 disabled("18년").

이름을 짓게 하고 기존 항목과 비교해 붙이는 방식(건당 3회)은 채택하지 않았다. 파편·과병합·프롬프트 예시 누출·반대 방향 혼입이 번갈아 났다. 고정 목록에서는 넷이 구조적으로 사라진다. 30건 시험에서 목록 밖 답 0건.

어휘 변경 규칙 · 아직 아닌 것

  1. 카테고리 추가는 patch (0.1.0 → 0.1.1). 기존 id 유지.
  2. 이름 변경은 label만. id는 안 바꾼다.
  3. 삭제·병합·id 변경은 minor. 기존 행 재분류 여부를 MR에 적는다.
  4. 추가 후보는 other 원문 중 여러 상품에 걸쳐 반복되는 문제만.
  • 시연 데이터의 intended_axis·generator는 생성 흔적. 계약 필드가 아니다.
  • scent_strong과 scent_artificial은 한 문장에 같이 나오는 일이 많다. 실데이터가 쌓이면 병합 여부를 본다.
  • 분류 정확도는 사람이 쓴 피드백으로만 잰다. 시연 99건은 성능 근거가 아니다.
