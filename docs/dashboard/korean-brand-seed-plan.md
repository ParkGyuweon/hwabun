## 0. 먼저 답해야 할 두 질문

### 0-1. "우리가 하려던 목적이 이게 맞나"

**절반만 맞다.** 기획 정리와 데이터 백로그가 못 박은 목적은 이것이다.

> 실제 소상공인이 상품을 등록한 서비스가 아니라, **"브랜드가 직접 등록하면 추천·대시보드·
> 참여 루프가 돌아간다" 를 재현 가능하게 증명하는 것.** (data-event-backlog §0)

이 목적에 필요한 것과 아닌 것을 가르면 이렇다.

| 필요하다 | 필요 없다 |
|---|---|
| **브랜드가 상품을 등록하는 폼**과 그 입력이 상세 페이지·추천 벡터로 변환되는 경로 (기획 §6, 계약 `product-registration-spec.md`) | 한국 브랜드 수십 개의 상품을 **긁어 와서** 200개 카탈로그를 통째로 갈아끼우는 것 |
| 발표에서 "진짜 소규모 브랜드가 이렇게 들어온다" 를 보여줄 **시드 몇 개** | 실제 브랜드의 리뷰·행동 로그 (없다. 있어도 못 가져온다) |
| Sephora 200개는 **추천 검증용으로 유지** (리뷰 84만 건이 여기에만 있다) | Sephora 를 버리는 것 — 버리면 Recall 수치와 페르소나가 전부 사라진다 |

즉 "한국 브랜드 데이터를 모아 오는 일" 자체가 목적이 아니다. **등록 폼이 목적**이고,
한국 브랜드는 그 폼이 진짜 데이터로도 돈다는 것을 보여 주는 **시드** 다. 시드는 10~20개면
충분하고, 폼으로 넣어야 의미가 있다(긁어 넣으면 폼이 증명되지 않는다).

### 0-2. "브랜드를 어떻게 선정하고 데이터를 어떻게 모으나"

**긁지 않는다. 폼으로 손으로 넣는다.** 이유 세 가지.

1. **법적·윤리적.** 상품 이미지·설명 문구는 브랜드 저작물이다. 스크래핑해서 우리 서비스에
   올리면 발표 자료에 남고, SSAFY 프로젝트라도 문제가 된다. 전성분·가격·용량은 화장품법상
   공개 표시 의무 항목이라 **사실 정보로 옮겨 적는 것은 괜찮다.** 이미지는 다르다.
2. **양이 안 맞다.** 소규모 브랜드는 품목이 한 자릿수다(식약처 통계, positioning §1-2).
   15개 브랜드 × 5~8개 = 100개 안팎. 손으로 넣을 수 있는 양이고, 그게 폼의 실사용 테스트다.
3. **리뷰가 없다.** 어디서 가져와도 우리 페르소나와 조인되는 리뷰는 없다. 시드 브랜드는
   콜드스타트로 시작하고 **신규 브랜드 전용 칸**(AI 회신, `reserved=2`)으로 노출된다.
   이것이 오히려 발표 서사에 맞는다 — "새로 들어온 브랜드가 자리를 얻는다".

## 1. 브랜드 선정 기준과 출처

### 1-1. 기준 (전부 만족)

| 기준 | 왜 |
|---|---|
| 책임판매업체 규모 10인 미만 추정 (자사몰 + 스마트스토어 정도만 운영) | 우리가 정의한 "소규모" (positioning §1-2) |
| **스킨케어** 중심, 우리 8개 secondary 카테고리 안에 있음 | 어휘집·추천 벡터가 스킨케어 기준 |
| 품목 5~12개 | 폼 입력 가능한 양, 추천 후보로 의미 있는 최소량 |
| 자사몰에 **전성분·가격·용량이 공개**돼 있음 | 법정 표시라 옮겨 적어도 되는 데이터 |
| 브랜드 스토리가 있음 (창업자 · 왜 만들었나) | 참여 루프 `brand_story` 체류 신호와 `participate` 성향의 재료 |
| 최근 1년 내 신제품 또는 활동 | 폐업 브랜드를 시드로 쓰지 않기 위해 |
| (가산) 성분·고민 포지션이 뚜렷함 | 배너 축(concern·ingredient)이 잘 붙는다 |

### 1-2. 후보를 찾는 곳 (`[공개]`)

| 출처 | 무엇을 얻나 |
|---|---|
| 올리브영 온라인 "인디 브랜드" · "신규 입점" 탭 | 최근 입점 소규모 브랜드 이름 |
| 무신사 뷰티 신진 브랜드 | 위와 같음, 온라인 중심 브랜드 |
| 화해 "새로 나온 브랜드" · 성분 랭킹 | 성분 포지션이 뚜렷한 브랜드 |
| 와디즈 뷰티 카테고리 펀딩 성공 | 1인·초기 브랜드, 스토리가 있음 |
| 각 브랜드 자사몰 (카페24·아임웹·스마트스토어) | **실제 데이터 원천.** 전성분·가격·용량·카테고리·브랜드 스토리 |
| 식약처 의약품안전나라 화장품 검색 | 책임판매업자명 확인 (브랜드 ↔ 업체 매핑) |

후보 30개를 모아 §1-1 로 걸러 **15개**를 고른다. 선정 표는 `docs/data/korean-brand-seed.md`
에 남기고, 각 브랜드에 출처 URL 과 확인 날짜를 적는다.

### 1-3. 하지 않는 것

- 브랜드에 연락해 허락을 받는 것 — 프로젝트 기간에 안 된다. 그래서 **이미지는 쓰지 않는다.**
- 대기업 자회사 인디 브랜드 (아모레 · LG 산하) — "소규모" 서사가 깨진다.
- 색조·헤어·바디 — 어휘집 밖이다.

## 2. 데이터를 어떤 형태로 만드나

### 2-1. 원칙: 등록 폼의 입력 형식이 곧 수집 템플릿이다

계약 `product-registration-spec.md` §3 이 정한 입력 필드가 전부다. 수집 스프레드시트의
열을 이것과 똑같이 두면, 스프레드시트 → 폼 입력 → JSON 이 한 형식이다.

| 열 | 입력 방식 | 어디서 옮겨 적나 | 저작물인가 |
|---|---|---|---|
| `brand_name` | 텍스트 | 자사몰 | 아니오 (명칭) |
| `product_name` | 텍스트 | 자사몰 | 아니오 (명칭) |
| `secondary_category` | 8종 선택 | 우리가 분류 | — |
| `tertiary_category` | 19종 선택 | 우리가 분류 | — |
| `highlights` | 30종 다중 선택 (concern 9 · clean 16 · texture 5) | 자사몰 표기를 보고 **우리가 태깅** | — |
| `ingredients` | 전성분 텍스트 | 자사몰 전성분표 | 아니오 (법정 표시) |
| `price_krw` | 숫자 | 자사몰 | 아니오 |
| `size` | 텍스트 ("50ml") | 자사몰 | 아니오 |
| `description.*` (what_it_is · suggested_usage · brand_story …) | 텍스트 | **우리가 요약해서 다시 쓴다.** 원문 복사 금지 | 원문은 저작물 |
| 이미지 | — | **넣지 않는다.** 플레이스홀더 + 브랜드 색 | 저작물 |
| `variants` | 있으면 용량·향 옵션명만 | 자사몰 | 아니오 |

발표 화면에서 이미지가 비어 보이는 것이 걱정이면, **시드 브랜드 카드에 "입점 브랜드 ·
이미지 준비 중" 배지** 를 두는 편이 남의 사진을 쓰는 것보다 낫다.

### 2-2. 변환 경로 — 이미 대부분 있다

```
수집 시트 (§2-1 열)
  → 폼 입력 (DB-03 / Jira 159)  ──────────────── 이것이 증명 대상
  → 등록 JSON  (계약 §7 저장 형식)
  → contracts/validate_product_registration.py   [있음]  어휘 밖 값 검사
  → 등록 파이프라인이 채우는 값 (계약 §4)        [AI]    price_usd 환산 · rating 주입 규칙
  → products_*.json 과 같은 형태                          Product 타입 그대로
  → product_feature 벡터 재생성 (어휘집 매칭)     [AI]
  → 추천 후보 + 신규 브랜드 전용 칸               [AI]    CF 이력 0 → reserved 로 노출
```

프론트 `Product` 타입과 등록 JSON 의 차이는 `image_url`(null) · `rating`(주입 규칙) ·
`review_count`(0) · `rank`(없음) · `suitable_skin_types` / `skincare_concerns`
(`highlights` 에서 파생) 정도다. **새 변환기가 필요 없다.**

### 2-3. 한국 브랜드가 들어오면 데이터 쪽에서 바뀌는 것 (데이터 파트 질문 8~14 와 같음)

| 항목 | 영향 | 담당 |
|---|---|---|
| 브랜드 원핫 블록 | 브랜드 55 → 70종. 벡터 맨 뒤 블록이 늘어나 **사용자 벡터 재계산** | AI |
| 가격 | `price_krw` → `price_usd` 환산 (계약 §4-1). `price_bin` 경계는 USD 유지 | AI |
| 리뷰 없음 | `attr_affinity` · `prior` 가 중립. 전용 칸으로만 노출 | AI |
| 어휘집 | 재생성 안 함. 한국 상품을 **기존 어휘에 매핑** (성분 30종은 INCI 영문명이라 전성분에 영문 병기된 브랜드가 유리) | 데이터·AI |

## 3. 단계 — 나눠서, 순서대로

| 단계 | 내용 | 산출물 | 담당 | 선행 |
|---|---|---|---|---|
| **A. 결정** | §0 두 답에 팀 합의: 시드 15개 · 폼으로 입력 · 이미지 안 씀 · Sephora 유지 | 이 문서에 결정 기록 | 전원 | — |
| **B. 선정** | §1 기준으로 후보 30 → 15. 브랜드별 출처·품목 수·카테고리 믹스 | `docs/data/korean-brand-seed.md` | PM · 프론트 | A |
| **C. 수집 템플릿** | §2-1 열 그대로 스프레드시트. 어휘 30종·카테고리 27종은 드롭다운 | 시트 + 작성 규칙 1쪽 | 프론트 | A |
| **D. 폼 = 상세 미리보기** | 등록 폼(Jira 159) 오른쪽에 **쇼핑몰 상세 페이지 컴포넌트를 그대로** 붙여 입력하는 즉시 보이게. `ProductDetailPage` 의 섹션 컴포넌트를 재사용 | 폼 화면 | 프론트 | 계약 §3 확정 |
| **E. AI 등록 보조** (Should) | 자유 텍스트 → 카테고리·highlights·용량 매핑 제안. 확정은 사람이 | 기획 §6 "상품 등록 보조" | AI · 프론트 | D |
| **F. 입력** | 15개 브랜드 × 5~8개를 **폼으로** 입력. 이것이 폼 실사용 테스트 | 등록 JSON ~100건 | 프론트 · PM | B · C · D |
| **G. 적재·검증** | validate → 파이프라인 → 벡터 재생성 → 전용 칸에 뜨는지 | 카탈로그 300개 (200 + 100) | 데이터 · AI | F |
| **H. 발표 서사** | "브랜드 사장님이 폼에 넣으면 5분 뒤 쇼룸과 추천에 뜬다" 시연 | 덱 슬라이드 | PM | G |

D 가 핵심이다. 사용자가 말한 "브랜드가 입력하면 알아서 상세 페이지 느낌으로 구성" 은
새 화면을 만드는 것이 아니라 **폼과 상세 페이지가 같은 컴포넌트를 쓰게 하는 것** 이다.
그래야 폼에서 본 미리보기와 소비자가 보는 화면이 한 픽셀도 다르지 않다.
