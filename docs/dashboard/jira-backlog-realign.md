## 0. 무엇이 바뀌어서 백로그가 흔들리나

| 결정 (2026-09-04) | 기존 백로그의 전제 | 영향 |
|---|---|---|
| **공동 쇼룸 하나** | 브랜드마다 각자 여는 브랜드스토어 (`storefront_*` 진열 축, tenant 전환) | 브랜드별 진열·테넌트 전환 이슈는 **브랜드 상세 페이지** 범위로 축소. 공동 쇼룸 헤더·브랜드 필터·통합 로그인이 새로 생김 |
| **참여 루프 ①~④** | 리뷰는 열람만, 피드백 이벤트 없음 | 구매자 리뷰·개선 피드백 작성, "반영됐어요" 알림, 상품 수정 이력이 Must 로 추가 |
| **브랜드가 직접 상품 등록** | 상품 200개는 적재 데이터 | 상품 등록 폼(코드표 기반) · 사업자 1:N 브랜드 · 사업자 인증 상태 5종 |
| **정산 Must** | 없음 | 주문 PAID 기준 · 수수료 0% · 월 단위 · PENDING/COMPLETED |
| **어드민 대시보드 Must** | 없음 | 브랜드 승인 · 상품 검수 · 추천 배너 관리 · 정산 상태 · 로그 모니터링 |
| **추천 배너 = 추천의 일부** | `promo_row` 피부 타입 규칙 | 추천 API 연결 + 성향 반응형 variant ([`personalized-banner-plan.md`](./personalized-banner-plan.md)) |
| **매출은 주문 DB, 로그는 전환 분석만** | `purchase` 이벤트로 매출 집계 검토 중 | `purchase_fact`(S15P21A306-101) 의 용도를 "전환 분석" 으로 한정. 정산은 백엔드 주문 테이블 |

git 이력에 보이는 기존 이슈 키는 12 · 17 · 25 · 29 · 65 · 72 · 75~79 · 81 · 82 · 91 · 94~101 이다.
제목은 Jira 에서 확인 후 §1 표의 "기존 키" 열에 채운다.

## 1. 기존 백로그 — 바꾸거나 닫을 것

| 주제 | 기존 키 | 조치 | 이유 |
|---|---|---|---|

| 중간발표 덱 구조 슬라이드 | (확인) | **수정** → 공동 쇼룸 · 함께 키운다 | positioning §4-1 |
| 이미지 캐시 · 필터 타입 수정 등 FE 버그 (`fix/*`) | (확인) | 유지 | 기획과 무관 |

## 3. 이번 주 스프린트 (9/7 월 ~ 9/11 금) 제안

원칙 세 가지.

1. **참여 루프 ①~④ 가 끝까지 한 번 돈다.** 이것이 발표의 차별점이라 다른 것보다 앞선다.
2. **공동 쇼룸으로 화면을 바꾼다.** 덱과 화면이 다르면 발표가 무너진다.
3. 정산 · 어드민은 **도메인과 API 까지만** 이번 주에 넣고 화면은 다음 주.

| 담당 | 이번 주 | 다음 주로 |
|---|---|---|
| **FE (추유림)** | FE-01 공동 쇼룸 헤더 · FE-04 세션 성향 계산기 · FE-05 히어로 배너 + variant · FE-03 추천 API 연결(BE-05 준비되면) | FE-06 · FE-10 · FE-12 |
| **FE (강하린)** | FE-07 리뷰 · 피드백 작성 폼 · FE-08 "반영됐어요" 알림 · FE-09 모의 결제 | DB-04 · DB-08 · FE-02 |
| **BE (최열음)** | BE-01 계정 · 사업자 · 브랜드 도메인 · BE-02 상품 CRUD · 주문 PAID · BE-03 리뷰 · 피드백 · BE-04 수정 이력 + 알림 | BE-05 · BE-06 · BE-07 |
| **Data (이은솔)** | DATA-02 optional 속성 · enum (프론트 발행이 이것에 걸려 있음, **월요일 답**) · DATA-01 purchase 활성화 · DATA-03 성과 마트 | DATA-04 · DATA-05 |
| **Data (송민우)** | 파이프라인 안정화 · AD-05 로그 모니터링 뷰 재료 · DATA-07 적재 경로 설계 | DATA-06 |
| **AI (박규원)** | AI-01 서빙 확정 · BE-05 와 API 계약 · AI-02 탐색 슬롯 결정(배너 포함 여부) | AI-03 · AI-04 |
| **공통** | 덱 구조 슬라이드 · Q&A 수정 (positioning §4-1) | — |

스프린트 목표 문장: **"공동 쇼룸에서 상품을 사고, 피드백을 남기고, 사장이 고치고, 고객이
'반영됐어요' 를 보는 것까지 한 번 돈다."**

## 4. Jira 반영 절차

1. §1 표의 "(확인)" 칸을 실제 키로 채운다 — 로그인 후 백로그를 읽어야 한다.
2. §1 조치대로 기존 이슈를 범위 축소 · 닫기 · 설명 수정.
3. §2 를 Epic 5개(소비자 쇼핑몰 · 대시보드 · 백엔드 · 데이터 · AI) 아래 Story 로 생성.
   ID 열(FE-01 등)은 생성 뒤 실제 키로 바꾼다.
4. §3 의 이번 주 항목을 스프린트에 넣고 담당자 배정.
5. 각 이슈 설명 첫 줄에 이 문서와 기획 정리의 절 번호를 링크한다.
