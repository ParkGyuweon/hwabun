# 서비스 기획 정리

## 0. 한 문장으로 보는 우리 플랫폼

우리 플랫폼은 **소규모 브랜드가 고객 의견을 제품에 반영하는 일을 쉽게 해 주는 플랫폼**입니다.

디마프는 직접 교육형 콘텐츠를 만들고, 고객을 팬덤으로 묶고, 제품 개발 단계부터 의견을 받으며 브랜드를 키웠습니다. 하지만 대부분의 1인·소규모 브랜드는 그만큼의 시간과 도구를 갖기 어렵습니다.

우리는 그 일을 플랫폼 기능으로 만들어 줍니다.

```text
플랫폼이 "의견 반영"을 쉽게 만든다
        ↓
소규모 브랜드가 모인다
        ↓
소비자가 온다
        ↓
소비자는 "내 의견이 반영되고, 브랜드를 같이 키운다"는 경험을 얻는다
        ↓
소비자 참여 데이터가 브랜드 대시보드가 된다
        ↓
브랜드는 고객 피드백을 제품 개선과 판매 전략에 반영한다
```

이 구조에서 소비자와 브랜드가 오는 이유는 하나의 흐름으로 이어집니다.

| 쪽 | 왜 오나 |
|---|---|
| 소비자 | 대기업에서는 내 의견이 수많은 의견 중 하나라 반영됐는지 알기 어렵지만, 여기서는 사장님이 읽고 바뀐 것을 볼 수 있어 브랜드를 같이 키우는 느낌을 얻을 수 있음 |
| 브랜드 | 혼자서는 하기 어려운 고객 피드백 수집, 팬덤 형성, 제품 개선 루프를 플랫폼이 대신 깔아주고, 피부 타입·고민별로 정리된 대시보드 인사이트를 얻을 수 있음 |

추천과 교차 발견은 이 구조의 입구입니다. 소비자를 참여할 브랜드와 만나게 하고, 한 브랜드의 고객이 다른 브랜드에도 의견을 남길 수 있게 합니다.

## 1. 우리가 만들 서비스

우리 서비스는 한마디로 **고객 피드백으로 함께 성장하는 뷰티 추천 플랫폼**입니다.

소비자가 보는 쇼핑몰은 하나입니다. 따라서 회원가입도 한 번만 하면 됩니다.

그 안에 여러 소규모 뷰티 브랜드의 상품을 모아두고, 사용자는 하나의 쇼핑몰처럼 상품을 탐색합니다. 브랜드 사장님은 대시보드에서 자신의 상품 성과와 고객 반응을 확인합니다.

이 서비스의 핵심은 단순히 여러 브랜드 상품을 모아 파는 것이 아닙니다.

> 소비자는 자신의 피부 고민에 맞는 상품을 추천받고, 사용 후 피드백을 통해 브랜드의 성장과 제품 개선에 참여합니다. 브랜드는 고객 피드백과 통합 인사이트를 바탕으로 상품과 판매 전략을 개선합니다.

즉, 여러 브랜드가 한 사이트에 모여 있기 때문에 가능한 **추천 + 피드백 + 성장형 커머스 플랫폼**입니다.

## 2. 왜 이 방향인가

단일 브랜드 자사몰만 대상으로 하면 상품 수가 너무 적어서 추천 알고리즘의 의미가 약해집니다. 반대로 올리브영이나 세포라처럼 단순히 여러 브랜드 상품을 모아 파는 대형 편집몰로 보이면 차별점이 부족합니다.

그래서 우리는 중간 지점을 선택합니다.

> 여러 소규모 뷰티 브랜드의 상품을 한 쇼핑몰에 모아두고, 사용자는 개인화 추천으로 상품을 탐색하며, 브랜드 사장님은 대시보드에서 상품 성과, 고객 반응, 정산 내역을 확인하는 구조입니다.

여기에 고객 피드백을 연결합니다.

> 소비자는 단순 구매자가 아니라, 자신의 리뷰와 피드백을 통해 브랜드가 더 좋은 상품을 만들도록 돕는 참여자가 됩니다.

소규모 브랜드는 대형 브랜드보다 고객 피드백을 더 빠르게 반영할 수 있습니다. 그래서 작은 브랜드라는 점을 약점이 아니라 **고객과 함께 성장할 수 있는 장점**으로 바꿉니다.

## 3. 개인 소비자 입장에서의 장점

개인 소비자는 이 플랫폼에서 단순히 상품을 구매하는 것이 아니라, 내 피부에 맞는 상품을 발견하고 브랜드의 성장에 참여할 수 있습니다.

| 이점 | 설명 |
|---|---|
| 내 피부 고민에 맞는 상품 추천 | 피부 타입, 피부 고민, 가격대, 성분 선호를 바탕으로 상품을 추천받음 |
| 화장품 구매 실패 감소 | 리뷰 수나 인기순만 보고 사는 것이 아니라 내 조건에 맞는 상품을 고름 |
| 여러 브랜드 상품을 한곳에서 비교 | 브랜드별 자사몰을 따로 찾아다니지 않아도 됨 |
| 한 번의 회원가입으로 이용 | 하나의 계정과 장바구니로 여러 브랜드 상품을 이용 |
| 내 피드백이 브랜드에 전달 | 리뷰, 불편사항, 개선 요청이 브랜드 대시보드에 반영됨 |
| 제품 개선 과정에 참여 | 체험단, 신상품 피드백, 리뷰를 통해 다음 제품 방향에 영향을 줄 수 있음 |
| 성장하는 브랜드를 함께 만드는 경험 | 소비자가 단순 구매자가 아니라 브랜드의 초기 팬이자 참여자가 됨 |
| 피드백 참여 혜택 | 리뷰 작성, 체험 피드백 참여 시 포인트나 할인 혜택을 받을 수 있음 |

소비자에게 가장 중요한 메시지는 다음입니다.

> 대형몰에서는 나는 수많은 구매자 중 한 명이지만, 이 플랫폼에서는 내 피부 반응과 피드백이 브랜드에게 전달되고 다음 제품 개선에 반영될 수 있습니다.

발표에서는 이렇게 말할 수 있습니다.

> 소비자는 자신의 피부 고민에 맞는 상품을 추천받고, 사용 후 피드백을 통해 브랜드의 제품 개선 과정에 참여할 수 있습니다. 단순히 상품을 사는 것이 아니라, 브랜드가 성장하는 과정에 함께 참여하는 경험을 제공합니다.

## 4. 왜 Sephora 데이터를 사용했나

우리 서비스는 여러 브랜드의 뷰티 상품이 한 사이트에 모여 있는 구조입니다. 따라서 추천 알고리즘도 **여러 브랜드가 섞여 있는 환경**에서 검증할 필요가 있습니다.

Sephora 데이터는 이 조건과 잘 맞습니다.

| 사용한 이유 | 설명 |
|---|---|
| 여러 브랜드가 함께 있음 | Sephora는 다양한 뷰티 브랜드 상품이 모여 있는 플랫폼이기 때문에, 우리 서비스와 비슷한 추천 환경을 만들 수 있음 |
| 상품과 리뷰가 함께 있음 | 상품 정보뿐 아니라 사용자 리뷰가 있어, 사용자의 선호와 상품 반응을 함께 볼 수 있음 |
| 뷰티 도메인 데이터임 | 스킨케어, 메이크업 등 우리 서비스와 같은 분야라 상품 속성과 사용자 관심사가 유사함 |
| 사용자 속성이 있음 | 피부 타입, 피부 톤, 머리색, 눈동자색 같은 정보가 있어 뷰티 추천에 필요한 개인화 기준을 만들 수 있음 |
| 추천 검증이 가능함 | 사용자의 과거 리뷰를 시드로 두고, 이후 좋아한 상품을 정답으로 두어 추천 성능을 평가할 수 있음 |
| 피드백 구조를 만들 수 있음 | 리뷰 내용을 분석해 고객이 어떤 점을 좋아하고 불편해하는지 브랜드 인사이트로 바꿀 수 있음 |

즉, Sephora 데이터를 쓴 이유는 단순히 공개 데이터라서가 아닙니다. **여러 브랜드가 한곳에 모인 뷰티 커머스 환경과 고객 리뷰 기반 피드백 구조를 가장 현실적으로 재현할 수 있기 때문입니다.**

### Sephora 상품을 사용한 이유

추천 알고리즘이 의미 있으려면 추천 후보 상품이 충분해야 합니다. 한 브랜드의 상품만 쓰면 상품 수가 적어 추천 결과가 제한됩니다.

Sephora 상품은 여러 브랜드의 다양한 상품이 포함되어 있어, 우리 서비스처럼 여러 브랜드 상품이 함께 있는 환경을 만들 수 있습니다.

또한 상품마다 카테고리, 가격, 브랜드, 상품 설명, 리뷰 등의 정보가 있어 콘텐츠 기반 추천과 속성 기반 추천을 만들기 좋습니다.

> Sephora 상품을 사용한 이유는 여러 브랜드가 섞인 추천 후보군을 만들고, 실제 뷰티 상품의 카테고리, 가격, 성분, 리뷰 정보를 기반으로 추천 알고리즘을 구성하기 위해서입니다.

### Sephora 페르소나를 사용한 이유

우리 서비스는 실제 사용자의 피부 타입, 관심사, 상품 반응을 기반으로 추천합니다. 하지만 프로젝트 단계에서는 실제 사용자를 충분히 모으기 어렵습니다.

그래서 Sephora 리뷰어 데이터를 기반으로 가상 페르소나를 만들었습니다.

Sephora 리뷰어는 단순한 임의의 가상 사용자가 아니라, 실제로 뷰티 상품에 리뷰를 남긴 사용자입니다.

| 정보 | 활용 |
|---|---|
| 과거에 좋게 평가한 상품 | 사용자 선호 시드로 사용 |
| 나중에 좋게 평가한 상품 | 추천이 맞혔는지 보는 정답으로 사용 |
| 피부 타입/피부 톤 등 속성 | 개인화 추천 기준으로 사용 |
| 리뷰 내용 | 성분, 가격, 제형, 향, 자극 등 행동 성향 추정에 사용 |
| 긍정/부정 피드백 | 브랜드 대시보드의 개선 인사이트로 활용 |

> Sephora 페르소나를 사용한 이유는 실제 뷰티 리뷰 이력을 가진 사용자를 기반으로, 피부 속성과 과거 선호가 반영된 추천 시나리오를 만들고, 리뷰 기반 고객 피드백 인사이트를 구성하기 위해서입니다.

## 5. 사용자 관점

사용자는 하나의 쇼핑몰에서 여러 소규모 뷰티 브랜드의 상품을 탐색합니다.

소비자가 보는 사이트는 하나이기 때문에 회원가입도 한 번만 하면 됩니다. 한 계정으로 여러 브랜드의 상품을 보고, 추천받고, 장바구니에 담고, 구매할 수 있습니다.

상품 추천은 단순 인기순이 아니라 사용자의 성향을 반영합니다.

| 사용자 성향 | 강조 문구 예시 |
|---|---|
| 가격을 많이 보는 사용자 | 할인, 가성비, 용량 대비 가격 |
| 성분을 중요하게 보는 사용자 | 성분, 무향, 민감성 테스트 |
| 리뷰를 많이 보는 사용자 | 리뷰 평점, 재구매 언급, 비슷한 피부 타입 후기 |
| 특정 피부 고민이 있는 사용자 | 진정, 보습, 트러블, 미백 등 |
| 브랜드 성장 참여형 사용자 | 신상품 체험, 개선 피드백, 브랜드 응원 |

이렇게 하면 추천 알고리즘이 단순히 “상품을 고르는 기능”이 아니라, 사용자에게 **왜 이 상품이 맞는지 보여주고, 사용 후 피드백까지 연결하는 개인화 경험**이 됩니다.

## 6. 브랜드 사장님 관점

브랜드 사장님은 **브랜드 대시보드**에 들어와서 본인의 브랜드와 상품을 관리합니다.

브랜드 등록 시에는 사업자등록번호 조회 API를 통해 사업자 정보를 확인합니다. 이를 통해 아무나 브랜드를 등록하는 것이 아니라, 실제 사업자임을 확인한 뒤 대시보드를 사용할 수 있게 합니다.

브랜드 사장님은 대시보드에서 상품 등록 버튼을 눌러 상품을 등록할 수 있습니다. 상품 등록 폼은 현재 프로젝트에서 사용하는 상품 데이터 구조에 맞춥니다.

| 항목 | 예시 |
|---|---|
| 상품명 | 진정 수분 세럼 |
| 브랜드명 | 브랜드 A |
| 카테고리 | 세럼, 크림, 토너 등 |
| 가격 | 32,000원 |
| 상품 설명 | 민감성 피부를 위한 진정 세럼 |
| 주요 성분 | 판테놀, 병풀, 히알루론산 |
| 피부 고민 태그 | 진정, 보습, 트러블 |
| 피부 타입 태그 | 건성, 지성, 민감성 등 |
| 상품 이미지 | 대표 이미지 |
| 용량 | 50ml |
| 판매 상태 | 판매 중, 품절 등 |

등록된 상품은 공동 플랫폼에 노출되고, 추천 후보에도 포함됩니다.

### 상품 등록 보조 기능

필수 기능은 아니지만, 브랜드 사장님이 상품을 더 쉽게 등록할 수 있도록 AI 상품 정보 정리 기능을 추가할 수 있습니다.

사장님이 상품 정보를 정해진 양식에 맞춰 하나하나 입력하지 않아도, 상품 설명이나 상세 페이지 내용을 자유롭게 넣으면 AI가 우리 데이터 구조에 맞게 정리합니다.

예를 들어 사장님이 이렇게 입력할 수 있습니다.

> “민감성 피부용 진정 세럼이고, 병풀추출물과 판테놀이 들어갔어요. 50ml에 32,000원이고 무향 제품입니다.”

그러면 AI가 다음처럼 정리합니다.

| 항목 | AI 매핑 결과 |
|---|---|
| 상품명 | 진정 세럼 |
| 카테고리 | 세럼 |
| 가격 | 32,000원 |
| 용량 | 50ml |
| 주요 성분 | 병풀추출물, 판테놀 |
| 피부 고민 태그 | 진정, 보습 |
| 피부 타입 태그 | 민감성 |
| 향 관련 태그 | 무향 |

이 기능은 단순 편의 기능이 아니라 **상품 등록 품질을 높여 추천 품질까지 도와주는 보조 기능**입니다.

### 정산 관리

여러 브랜드가 한 쇼핑몰에 함께 입점하는 구조이기 때문에 브랜드별 정산 기능은 필수 기능입니다.

사용자가 여러 브랜드의 상품을 함께 구매하더라도, 각 주문 상품이 어떤 브랜드의 상품인지 구분해서 브랜드별 매출을 계산해야 합니다.

매출과 정산은 행동 로그가 아니라 **백엔드의 결제 완료 주문 데이터**를 기준으로 계산합니다. 행동 로그의 `purchase` 이벤트는 전환 분석에만 사용하고, 정산 근거로는 사용하지 않습니다.

프로젝트 범위에서는 플랫폼 수수료를 **0%**로 둡니다. 따라서 정산 예정 금액은 결제 완료된 주문 상품 금액과 같습니다.

| 항목 | 의미 |
|---|---|
| 총 판매 금액 | 해당 기간 동안 브랜드 상품이 판매된 총 금액 |
| 정산 예정 금액 | 수수료 0% 기준으로 브랜드에게 지급될 금액 |
| 주문별 정산 내역 | 어떤 주문에서 어떤 상품이 판매되었는지 |
| 상품별 판매 금액 | 상품별 매출 기여도 |
| 정산 상태 | 정산 예정, 정산 완료 등 |
| 정산 기간 | 월별 정산 기준 |

정산 기능이 있어야 브랜드 사장님 입장에서 “내 상품이 팔렸고, 얼마를 받을 수 있는지”를 확인할 수 있습니다.

따라서 정산은 단순 부가 기능이 아니라 **입점형 플랫폼 구조를 성립시키는 필수 기능**입니다.

정산 계산식은 다음과 같습니다.

```text
총 판매 금액 = 결제 완료 주문 상품 금액 합계
수수료 = 총 판매 금액 × 0%
정산 예정 금액 = 총 판매 금액
```

## 7. 브랜드 대시보드와 어드민 대시보드

대시보드는 두 종류로 나눕니다.

| 대시보드 | 사용자 | 목적 |
|---|---|---|
| 브랜드 대시보드 | 브랜드 사장님 | 내 상품의 성과를 보고 판매율과 제품을 개선하는 것 |
| 어드민 대시보드 | 서비스 관리자/개발자 | 입점 브랜드, 상품, 배너, 운영 상태를 관리하는 것 |

### 브랜드 대시보드

브랜드 대시보드는 사장님이 자신의 브랜드를 운영하는 화면입니다.

여기서는 단순 매출만 보여주는 것이 아니라, 판매율과 제품을 개선하는 데 쓸 수 있는 **고객 피드백 기반 집단 인사이트**를 제공합니다.

집단 인사이트란, 한 브랜드의 자사몰만으로는 알기 어려운 정보입니다. 여러 브랜드의 상품이 한 사이트에 모여 있기 때문에 비교할 수 있는 정보입니다.

예시는 다음과 같습니다.

> “당신의 3만원대 진정 세럼은 같은 조건의 상품보다 장바구니 담기율이 낮습니다.”  
> “건성 사용자에게는 반응이 좋지만, 지성 사용자에게는 상세 페이지 이탈이 많습니다.”  
> “리뷰에서는 ‘보습’ 만족도가 높은데, 상품 태그는 ‘진정’ 중심으로 등록되어 있습니다.”  
> “이번 달 상품 조회의 38%는 다른 브랜드 상품을 보러 온 고객에게서 발생했습니다.”

| 기능 | 의미 |
|---|---|
| 상품 성과 확인 | 조회수, 클릭률, 장바구니 담기율, 구매 전환율 확인 |
| 통합 인사이트 확인 | 비슷한 상품군/가격대/고객군과 비교한 내 상품 위치 확인 |
| 고객군별 반응 확인 | 피부 타입, 가격 민감도, 성분 선호별 반응 확인 |
| 피드백 키워드 분석 | 고객 리뷰에서 반복되는 만족/불만 키워드 확인 |
| 개선 요청 모음 | 고객이 남긴 불편사항과 바라는 점 확인 |
| 다음 제품 아이디어 | 고객 피드백을 기반으로 개선 방향 제안 |
| 상품 등록/수정 | 브랜드 상품을 직접 등록하고 수정 |
| 정산 확인 | 브랜드별 판매 금액과 정산 예정 금액 확인 |
| 프로모션 신청 | 신상품 또는 캠페인 상품의 노출 신청 |

### 어드민 대시보드

어드민 대시보드는 서비스 관리자나 개발자가 운영하는 화면입니다.

여기서는 각 브랜드와 상품이 정상적으로 등록되고 운영되는지 관리합니다.

| 기능 | 의미 |
|---|---|
| 브랜드 관리 | 입점 신청 승인, 사업자 인증 상태 확인, 브랜드 정보 수정 |
| 상품 관리 | 등록 상품 검수, 판매 상태 관리, 품절/판매중 상태 확인 |
| 추천 배너 관리 | 추천 배너 등록, 노출 위치 설정, 대상 사용자군 설정 |
| 추천 운영 관리 | 추천 후보 상품, 신상품 탐색 슬롯, 노출 정책 확인 |
| 이벤트/로그 모니터링 | 클릭, 조회, 장바구니, 구매 이벤트가 정상 수집되는지 확인 |
| 정산 관리 | 브랜드별 매출, 수수료 0% 기준 정산 상태 확인 |
| 신고/비정상 데이터 확인 | 잘못된 상품 정보나 이상 로그 확인 |

즉, 브랜드 대시보드는 **사장님이 보는 성장 도구**이고, 어드민 대시보드는 **서비스 운영자가 보는 관리 도구**입니다.

## 8. 고객 피드백이 브랜드 성장으로 이어지는 구조

이 서비스의 중요한 차별점은 고객 피드백이 브랜드에게 전달되고, 브랜드의 상품 개선과 다음 제품 방향에 영향을 줄 수 있다는 점입니다.

```text
소비자 상품 탐색/구매
→ 피부 타입과 함께 리뷰·피드백 작성
→ 브랜드 대시보드에서 피드백 분석
→ 상품 설명, 태그, 가격, 프로모션, 다음 제품 방향 개선
→ 소비자는 내 의견이 반영되는 경험을 얻음
```

예를 들어 소비자는 다음과 같은 피드백을 남길 수 있습니다.

| 피드백 | 브랜드가 얻는 정보 |
|---|---|
| “보습은 좋은데 향이 강해요” | 향 조절 또는 무향 라인 검토 |
| “민감성 피부인데 따갑지 않았어요” | 민감성 고객군에게 강조할 문구 확보 |
| “가격이 조금 부담돼요” | 소용량/체험가/세트 구성 검토 |
| “제형이 끈적이지 않아서 좋아요” | 상세페이지에서 제형 장점 강조 |
| “트러블 피부에도 괜찮았어요” | 트러블 피부 타겟 문구 보완 |

소비자는 단순히 리뷰를 남기는 것이 아니라, 브랜드가 더 나은 상품을 만들도록 돕는 참여자가 됩니다.

브랜드는 고객의 목소리를 모아 상품 설명, 추천 태그, 가격 전략, 다음 제품 방향에 반영할 수 있습니다.

## 9. 자사몰과 다른 점

브랜드 사장님 입장에서 우리 서비스가 자사몰과 다른 점은 세 가지입니다.

첫째, **비슷한 규모의 브랜드끼리 경쟁합니다.** 대형 브랜드와 한 공간에서 경쟁하는 것이 아니라, 소규모 뷰티 브랜드들이 모인 플랫폼 안에서 노출됩니다. 그래서 작은 브랜드도 고객에게 발견될 가능성이 있습니다.

둘째, **통합 인사이트를 얻을 수 있습니다.** 자사몰에서는 자기 브랜드 안에서만 데이터를 볼 수 있습니다. 하지만 우리 서비스에서는 비슷한 규모의 다른 브랜드들과 비교해 내 상품이 어느 지점에서 강하고 약한지 볼 수 있습니다.

셋째, **다른 브랜드 상품을 보러 온 사용자에게도 내 상품을 노출할 수 있습니다.** 자사몰은 이미 내 브랜드를 아는 사람이 들어오는 구조입니다. 반면 우리 플랫폼에서는 다른 브랜드 상품을 보러 온 사용자도 추천을 통해 내 상품을 발견할 수 있습니다.

즉, 우리 서비스는 단순히 상품을 올리는 공간이 아니라 **소규모 브랜드가 새로운 고객에게 발견되고, 비교 인사이트와 고객 피드백을 얻는 공간**입니다.

## 10. 통합 인사이트 추천 순위

통합 인사이트는 “자사몰만 운영했다면 알기 어려운 정보”를 우선으로 둡니다. 즉, 여러 브랜드가 함께 모여 있기 때문에 알 수 있는 정보를 중심으로 제공합니다.

### 1순위. 같은 조건 상품 대비 내 상품 위치

자사몰에서는 내 상품의 전환율이 높은지 낮은지 판단하기 어렵습니다. 하지만 여러 브랜드 상품이 함께 있으면 비슷한 상품끼리 비교할 수 있습니다.

예시:

> “3만원대 진정 세럼 중 장바구니 전환율이 하위 25%입니다.”  
> “같은 가격대·같은 카테고리 상품의 중앙값은 4.8%, 내 상품은 2.1%입니다.”

### 2순위. 고객군별 강점과 약점

어떤 고객에게 잘 맞고, 어떤 고객에게 약한지 보여줍니다.

예시:

> “건성 사용자에게는 평균보다 반응이 좋지만, 지성 사용자는 상세 페이지에서 많이 이탈합니다.”  
> “민감성 피부 사용자는 장바구니 담기율이 높지만, 복합성 피부 사용자는 클릭 후 이탈이 많습니다.”

### 3순위. 고객 피드백 기반 개선 포인트

소규모 브랜드의 장점은 고객 피드백을 빠르게 반영할 수 있다는 점입니다. 따라서 리뷰와 피드백에서 반복되는 만족/불만 키워드를 뽑아 브랜드에게 제공합니다.

예시:

> “리뷰에서는 ‘보습’ 만족도가 높지만, 상품 태그는 ‘진정’ 중심입니다.”  
> “민감성 사용자는 자극이 적다고 평가했지만, 향이 강하다는 불만이 반복됩니다.”  
> “가격 부담 언급이 많아 소용량 또는 첫 구매 할인 구성이 필요합니다.”

### 4순위. 다른 브랜드 방문자 유입 효과

자사몰에서는 원래 내 브랜드를 아는 사람이 주로 들어옵니다. 하지만 우리 플랫폼에서는 다른 브랜드 상품을 보러 온 사용자에게도 내 상품이 추천될 수 있습니다.

예시:

> “이번 달 상품 조회의 38%는 다른 브랜드 상품을 보러 온 고객에게서 발생했습니다.”  
> “내 브랜드를 처음 본 사용자 중 22%가 추천 영역을 통해 유입되었습니다.”

### 5순위. 가격대 적합성

가격은 소규모 브랜드 사장님이 가장 민감하게 보는 요소입니다.

예시:

> “같은 카테고리에서 2~3만원대 상품은 전환율이 높고, 5만원대 상품은 이탈률이 높습니다.”  
> “내 상품은 같은 상품군 평균보다 가격이 높고, 장바구니 단계에서 이탈이 많습니다.”

### 6순위. 키워드/태그 반응 차이

브랜드가 강조하는 포인트와 고객이 실제로 반응하는 포인트는 다를 수 있습니다.

예시:

> “브랜드는 ‘진정’을 강조했지만, 고객 반응은 ‘보습’ 키워드에서 더 높습니다.”  
> “등록 태그는 ‘트러블’ 중심이지만, 리뷰와 클릭 반응은 ‘저자극’에서 더 높습니다.”

### 7순위. 추천 노출 대비 클릭률

추천 영역에 노출됐을 때 실제로 클릭되는지를 보여줍니다.

예시:

> “추천에는 자주 노출되지만 클릭률은 같은 상품군보다 낮습니다.”  
> “노출은 적지만 클릭률은 높아, 더 많이 노출해볼 가치가 있습니다.”

### 8순위. 신상품 초기 반응

신상품은 데이터가 적기 때문에 자사몰에서는 반응 판단이 늦습니다. 하지만 공동 플랫폼에서는 여러 사용자에게 탐색 슬롯으로 노출해 초기 반응을 더 빨리 볼 수 있습니다.

예시:

> “신상품 탐색 슬롯에서 같은 카테고리 신상품보다 클릭률이 높습니다.”  
> “조회는 충분하지만 장바구니 담기가 낮아 상세 설명 보완이 필요합니다.”

### 9순위. 상세 페이지 이탈 구간

사용자가 어디서 관심을 잃는지 보여줍니다.

예시:

> “상세 페이지 진입은 평균 이상이지만, 장바구니 담기 전 이탈이 높습니다.”  
> “추천 클릭 후 체류 시간이 짧아, 첫 화면 정보 전달을 보완해야 합니다.”

## 11. 추천 알고리즘 방향

여러 브랜드가 함께 입점하는 구조에서는 같은 브랜드 상품만 반복 추천하면 플랫폼의 장점이 약해집니다.

따라서 추천 알고리즘은 **브랜드 일치보다 상품 자체의 유사도와 사용자 선호 적합도**를 더 크게 반영하는 방향이 좋습니다.

| 항목 | 방향 |
|---|---|
| 상품 유사도 | 높게 반영 |
| 사용자 피부/속성 적합도 | 높게 반영 |
| 사용자의 행동 기반 선호 | 높게 반영 |
| 같은 브랜드 보너스 | 낮게 반영 |
| 유사 브랜드 보너스 | 약하게 반영 |
| 인기도 | 보조적으로 반영 |
| 신상품/저노출 상품 | 탐색 슬롯으로 일부 반영 |

즉, 추천은 이렇게 가야 합니다.

> 같은 브랜드를 반복 추천하는 것이 아니라, 사용자가 좋아할 만한 비슷한 상품을 여러 브랜드에서 발견하게 하는 구조.

### 브랜드 간 유사도 계산

브랜드 간 유사도도 계산할 수 있습니다. 브랜드 이름이 비슷한지를 보는 것이 아니라, **상품 구성과 고객 반응이 비슷한지**를 봅니다.

| 기준 | 의미 |
|---|---|
| 상품 속성 유사도 | 카테고리, 가격대, 성분, 피부 고민, 제형이 비슷한가 |
| 고객 반응 유사도 | 같은 사용자가 두 브랜드 상품을 함께 조회/장바구니/구매했는가 |
| 리뷰/설명 유사도 | 리뷰나 상품 설명에서 비슷한 키워드가 나오는가 |
| 가격대 유사도 | 주력 상품 가격대가 비슷한가 |
| 고객군 유사도 | 반응이 좋은 피부 타입이나 선호 성향이 비슷한가 |

예시 계산식은 다음과 같습니다.

```text
brand_similarity(A, B)
= 0.40 × 상품 속성 유사도
+ 0.30 × 고객 반응 유사도
+ 0.20 × 리뷰/설명 유사도
+ 0.10 × 가격대 유사도
```

브랜드 유사도는 추천과 대시보드 양쪽에 활용할 수 있습니다.

| 활용 | 예시 |
|---|---|
| 추천 | A 브랜드를 본 사용자에게 비슷한 B 브랜드 상품 추천 |
| 대시보드 | “유사 브랜드 대비 내 상품 전환율이 낮습니다” 제공 |
| 추천 배너 | 유사 브랜드 방문자에게 내 브랜드 상품 배너 노출 |
| 신규 브랜드 콜드 스타트 | 아직 데이터가 적은 브랜드를 비슷한 상품군 사용자에게 노출 |

## 12. 추천 배너와 추천 알고리즘

우리가 말하는 광고 배너는 돈을 받고 띄워주는 유료 광고 상품이 아닙니다. 추천의 일종입니다.

즉, 추천 알고리즘이 고른 상품 중에서 사용자에게 더 눈에 띄게 보여줄 필요가 있는 상품을 배너 형태로 노출하는 것입니다.

그래서 문서에서는 “광고 배너”보다 **추천 배너** 또는 **프로모션 추천 영역**이라고 표현하는 것이 더 정확합니다.

| 표현 | 의미 |
|---|---|
| 추천 배너 | 추천 결과를 더 눈에 띄게 보여주는 배너 영역 |
| 프로모션 추천 영역 | 추천 결과 중 강조하고 싶은 상품을 배너 형태로 노출 |
| 신상품 탐색 슬롯 | 신규 상품 데이터를 쌓기 위한 추천 영역. 추천 배너에 포함할지는 추가 결정 필요 |

### 추천 배너의 역할

| 역할 | 의미 |
|---|---|
| 추천 상품의 노출 강화 | 추천 결과 중 강조할 상품을 더 눈에 띄는 위치에 보여줌 |
| 신규 브랜드 노출 | 아직 행동 데이터가 적은 브랜드도 적합한 사용자에게 보일 기회를 얻음. 추천 배너 포함 여부는 추가 결정 필요 |
| 신상품 데이터 수집 | 신상품을 일부 사용자에게 노출해 클릭, 조회, 장바구니 데이터를 쌓음. 추천 배너 포함 여부는 추가 결정 필요 |
| 고객군 반응 테스트 | 어떤 피부 타입/성향 사용자에게 반응이 좋은지 확인 |
| 문구 반응 테스트 | 할인 강조, 성분 강조, 리뷰 강조 등 어떤 메시지가 효과적인지 비교 |
| 추천 콜드 스타트 완화 | 데이터가 적은 상품도 초기 반응을 얻어 추천에 반영할 수 있음 |

### 추천 알고리즘에 반영하는 방식

추천 배너가 추천 알고리즘에 영향을 주려면, 배너를 본 뒤의 사용자 행동을 이벤트로 수집해야 합니다.

| 이벤트 | 의미 |
|---|---|
| `banner_impression` | 추천 배너가 사용자에게 노출됨 |
| `banner_click` | 사용자가 추천 배너를 클릭함 |
| `product_view` | 배너를 통해 상품 상세를 봄 |
| `add_to_cart` | 장바구니에 담음 |
| `purchase` | 구매함 |
| `banner_skip` | 노출됐지만 클릭하지 않음 |

이 데이터가 쌓이면 추천 알고리즘은 다음을 학습할 수 있습니다.

| 행동 | 추천 반영 |
|---|---|
| 추천 배너 클릭 후 상세 조회 | 해당 상품/카테고리에 약한 관심 신호 |
| 상세 페이지 오래 체류 | 해당 상품 속성에 중간 관심 신호 |
| 장바구니 담기 | 강한 긍정 신호 |
| 구매 | 가장 강한 긍정 신호 |
| 추천 배너를 반복적으로 무시 | 해당 상품/브랜드/문구에 낮은 관심 신호 |

중요한 점은 다음입니다.

> 추천 배너는 상품을 억지로 띄우는 장치가 아니라, 추천 결과를 더 잘 보이게 만들고 그 반응을 다시 추천에 반영하는 장치입니다.

즉, 추천에는 “배너에 걸렸는가”가 아니라 **배너를 본 사용자가 실제로 어떻게 반응했는가**를 반영합니다.

## 13. 대시보드에서 브랜드가 보는 것

브랜드 사장님은 단순 매출만 보는 것이 아니라, 자기 상품이 어떤 고객에게 잘 맞고 어디서 이탈되는지 확인합니다.

| 인사이트 | 의미 |
|---|---|
| 상품별 조회 수 | 어떤 상품을 많이 봤는지 |
| 장바구니 담기율 | 본 사람 중 몇 명이 담았는지 |
| 피부 타입별 반응 | 건성, 지성, 민감성 사용자 중 누가 반응했는지 |
| 가격대 반응 | 현재 가격대가 고객에게 맞는지 |
| 성분/태그 반응 | 어떤 성분이나 고민 태그가 반응을 얻었는지 |
| 고객 피드백 키워드 | 리뷰에서 자주 나오는 만족/불만 포인트 |
| 개선 요청 | 고객이 반복해서 말하는 바라는 점 |
| 추천 노출 대비 클릭률 | 추천에 떴을 때 실제로 클릭했는지 |
| 이탈 구간 | 상세 페이지에서 나갔는지, 장바구니에서 멈췄는지 |
| 추천 배너 반응 | 추천 배너로 노출됐을 때 클릭/조회/장바구니로 이어졌는지 |
| 정산 내역 | 상품 판매 금액과 브랜드별 정산 예정 금액 |

이렇게 하면 브랜드는 단순히 상품을 올리는 데서 끝나지 않고, 고객 반응을 보고 상품 설명, 가격, 태그, 추천 배너 문구, 다음 제품 방향, 매출 정산까지 관리할 수 있습니다.

## 14. 왜 여러 브랜드가 필요한가

추천 알고리즘이 의미 있으려면 추천할 후보 상품이 충분해야 합니다.

단일 브랜드만 대상으로 하면 상품 수가 적어서 추천 결과가 뻔해질 수 있습니다. 예를 들어 한 브랜드에 상품이 10개밖에 없다면, 추천 알고리즘이 아무리 좋아도 선택지가 너무 적습니다.

그래서 여러 소규모 브랜드가 입점하는 구조가 필요합니다.

> 여러 브랜드의 상품을 모아 약 200개 수준의 추천 후보를 확보한다. 이를 통해 추천 알고리즘이 실제로 상품을 고르는 의미가 생긴다.

다만 목적은 올리브영처럼 대형 편집몰이 되는 것이 아닙니다.

우리의 핵심은 다음입니다.

> 소규모 브랜드가 직접 상품을 등록하고, 사용자는 개인화 추천으로 상품을 발견하고 피드백을 남기며, 브랜드는 대시보드에서 고객 반응, 비교 인사이트, 정산 내역을 확인하는 것.

## 15. 반드시 확정한 운영 기준

### 1. 사업자와 브랜드의 관계

사업자 1명이 여러 브랜드를 운영할 수 있습니다. 상품은 브랜드에 소속되고, 브랜드는 사업자에게 소속됩니다.

사업자 인증과 로그인 권한은 사업자 기준으로 관리합니다.

```text
사업자 1 ── N 브랜드 1 ── N 상품
```

기획 문구:

> 입점 사업자는 하나 이상의 브랜드를 등록하고 관리할 수 있다.

### 2. 매출과 정산의 기준

매출과 정산은 백엔드 주문 DB를 기준으로 계산합니다.

행동 로그의 `purchase` 이벤트는 구매 전환 분석에만 사용하고, 정산 근거로는 사용하지 않습니다.

매출에 포함되는 것은 결제 완료된 주문뿐입니다. 장바구니 담기나 주문 생성만으로는 매출에 포함하지 않습니다.

기획 문구:

> 매출과 정산 금액은 결제 완료된 주문 데이터를 기준으로 산출하며, 행동 로그는 정산 근거로 사용하지 않는다.

### 3. 정산 단위와 대시보드 표시 단위

실제 정산 주체는 사업자입니다. 정산은 사업자별·정산 기간별로 처리합니다.

다만 대시보드에서는 사업자 전체, 브랜드별, 상품별로 나눠서 볼 수 있게 합니다.

한 주문에 여러 브랜드 상품이 들어 있으면 주문 상품별로 사업자에게 귀속합니다.

기획 문구:

> 정산은 사업자 단위로 처리하며, 정산 상세 내역은 브랜드 및 상품별로 구분해 제공한다.

### 4. 수수료 정책

프로젝트 범위에서는 플랫폼 수수료를 **0%**로 둡니다.

브랜드별 개별 수수료, 프로모션 수수료, 차등 수수료는 구현하지 않습니다.

```text
총 판매 금액 = 결제 완료 주문 상품 금액 합계
수수료 = 총 판매 금액 × 0%
정산 예정 금액 = 총 판매 금액
```

기획 문구:

> 프로젝트 범위에서는 플랫폼 수수료를 0%로 적용한다.

### 5. 정산 주기와 상태

정산은 프로젝트 단순화를 위해 **월 단위**로 집계합니다.

정산 상태는 두 개만 사용합니다.

```text
PENDING    정산 예정
COMPLETED  정산 완료
```

실제 송금 기능까지 구현하지 않고, 관리자가 정산 완료 상태로 변경하는 방식으로 처리합니다.

기획 문구:

> 정산은 월 단위로 집계하며, 정산 예정과 정산 완료 상태를 제공한다.

### 6. 구매 완료의 정의

장바구니 담기는 구매가 아닙니다. 주문 생성만으로도 매출에 포함하지 않습니다.

주문 상태가 `PAID`가 된 시점을 구매 완료로 봅니다.

실제 PG를 붙이지 않는다면 프로젝트용 결제 완료 버튼이나 모의 결제 성공 처리를 사용합니다.

기획 문구:

> 구매는 주문의 결제 완료 상태를 기준으로 판정하며, 장바구니 및 주문 생성 단계는 매출에 포함하지 않는다.

### 7. 브랜드 대시보드 접근 범위

사업자는 자기 사업자 계정에 연결된 브랜드만 볼 수 있어야 합니다.

브랜드 대시보드에서는 다음 범위의 데이터를 제공합니다.

| 범위 | 설명 |
|---|---|
| 사업자 전체 통합 현황 | 사업자가 운영하는 모든 브랜드의 전체 요약 |
| 특정 브랜드 선택 | 브랜드별 상세 조회 |
| 브랜드별 상품 성과 | 조회수, 클릭률, 장바구니율, 구매율 |
| 브랜드별 리뷰·피드백 | 고객 리뷰와 개선 요청 |
| 브랜드별 매출 | 브랜드 기준 판매 금액 |
| 사업자 전체 정산 금액 | 사업자에게 지급될 월별 정산 예정 금액 |

기획 문구:

> 사업자는 자신의 계정에 연결된 브랜드 전체 현황을 확인할 수 있으며, 브랜드별로 상품 성과·고객 반응·매출 내역을 조회할 수 있다.

### 8. 사업자 인증 상태

사업자 인증은 단순 성공/실패만 두지 않고, 상태를 나눠서 관리합니다.

```text
PENDING       인증 전 또는 확인 중
VERIFIED      진위확인 완료
MISMATCH      입력 정보 불일치
RETRY_NEEDED  API 오류 또는 일시적 조회 불가
INACTIVE      휴업 또는 폐업 상태
```

사업자등록번호는 사업자에 귀속시키고, 브랜드에 직접 귀속시키지 않습니다.

기획 문구:

> 사업자 인증은 진위 여부와 영업 상태를 구분해 관리하며, 인증된 사업자만 브랜드와 상품을 등록할 수 있다.

### 9. 다른 브랜드 방문자 유입 정의

한 세션에서 최초로 조회한 상품의 브랜드와 이후 조회한 상품의 브랜드가 다르면 교차 브랜드 유입으로 집계합니다.

예시는 다음과 같습니다.

```text
A 브랜드 상품 조회
→ 추천 영역에서 B 브랜드 상품 클릭
→ B 브랜드 상품 상세 조회

B 브랜드의 교차 브랜드 유입 1건
```

지표는 두 가지로 분리합니다.

| 지표 | 의미 |
|---|---|
| 교차 브랜드 유입 | 일반 탐색까지 포함한 다른 브랜드 유입 |
| 추천 기반 교차 브랜드 유입 | 추천 영역을 통해 발생한 다른 브랜드 유입 |

기획 문구:

> 한 세션에서 최초 조회 브랜드와 이후 조회 브랜드가 다른 경우 교차 브랜드 유입으로 집계하며, 추천을 통한 유입은 별도 지표로 분리한다.

### 10. 추천 배너의 범위

추천 배너는 유료 광고가 아닙니다. 개인화 추천 결과를 더 눈에 띄게 보여주는 추천 노출 영역입니다.

확정된 범위는 다음과 같습니다.

| 기준 | 내용 |
|---|---|
| 역할 | 추천 알고리즘 결과를 강조해서 보여주는 영역 |
| 유료 광고 여부 | 광고비·입찰·유료 노출 기능 아님 |
| 추천 신호 | 노출 자체는 선호 신호로 쓰지 않음 |
| 추천 반영 | 클릭, 상세 조회, 장바구니 반응만 추천에 활용 |

아직 결정이 필요한 사항은 하나입니다.

> 추천 배너에 신상품·저노출 상품을 포함할지 여부

포함한다면 추천 배너는 신상품 콜드 스타트 완화에도 사용할 수 있습니다. 포함하지 않는다면 추천 배너는 순수 개인화 추천 결과를 강조하는 영역으로만 둡니다.

기획 문구:

> 추천 배너는 유료 광고가 아니라 개인화 추천 결과를 강조하는 노출 영역이다.

### 11. 리뷰·피드백 작성 기준

리뷰와 피드백은 구매 완료 사용자만 작성할 수 있습니다.

기준은 다음과 같습니다.

| 기준 | 내용 |
|---|---|
| 작성 가능 사용자 | 결제 완료 사용자 |
| 작성 단위 | 주문 상품 1개당 리뷰 1개 |
| 수정 | 가능 |
| 삭제·숨김 | 상태 관리 |
| 입력 내용 | 평점과 개선 피드백을 함께 입력 |
| 리뷰 포인트 | 후순위 기능 |

기획 문구:

> 결제 완료된 주문 상품에 대해 구매자만 리뷰와 개선 피드백을 작성할 수 있으며, 주문 상품당 하나의 리뷰를 작성할 수 있다.

### 12. 비교 인사이트 제공 조건

소규모 브랜드는 데이터가 적기 때문에 비교 지표가 항상 나오지는 않습니다.

표본이 충분할 때만 비교 결과를 제공하고, 표본이 부족하면 숫자를 억지로 만들지 않고 “데이터 수집 중”으로 표시합니다.

다른 브랜드의 이름과 절대 매출은 공개하지 않습니다. 유사 브랜드의 중앙값, 범위, 분위 같은 익명 집계값만 제공합니다.

기획 문구:

> 비교 인사이트는 충분한 표본이 확보된 경우 익명화된 유사 브랜드 집계값으로 제공하며, 표본이 부족하면 데이터 수집 중으로 표시한다.

| 왜 정산 기능이 필요한가? | 여러 브랜드 상품이 함께 판매되므로 브랜드별 매출을 나눠야 하기 때문에 |
| 왜 취소/환불은 Should인가? | 실제 서비스에는 필요하지만 프로젝트 구현 범위에서는 복잡도가 높기 때문에 |
| 왜 추천 배너가 필요한가? | 추천 상품의 노출도를 높이고, 사용자가 중요한 추천 결과를 더 잘 발견하게 하기 위해 |
| 추천 배너가 추천 알고리즘에 영향을 주는 방식은? | 배너 노출 자체가 아니라 배너 이후의 실제 사용자 반응을 추천 신호로 반영하기 때문 |
| 왜 브랜드 다양성 제어가 필요한가? | 같은 브랜드 상품만 반복 추천되면 공동 플랫폼의 장점이 약해지기 때문 |
| 왜 브랜드 가중치를 낮추는가? | 다른 브랜드 상품도 발견될 수 있게 상품 유사도와 사용자 선호를 더 크게 보기 위해 |
| 자사몰과 뭐가 다른가? | 다른 브랜드 방문자에게 노출되고, 비슷한 규모 브랜드와 비교한 통합 인사이트와 고객 피드백을 얻을 수 있기 때문 |
| 기존 편집몰과 뭐가 다른가? | 단순 판매몰이 아니라 추천, 고객 피드백, 데이터 인사이트를 함께 제공하는 플랫폼이기 때문 |
