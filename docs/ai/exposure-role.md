# 노출은 어디서 무엇을 하는가

> 2026-09-04 · AI 파트
> **묻는 것:** 지금 알고리즘에서 "노출" 이 맡은 역할이 무엇인가.
> 한 단어가 다섯 군데에서 서로 다른 일을 하고 있어, 어느 자리 이야기인지 먼저
> 정하지 않으면 대화가 어긋납니다.

한 줄로 답하면 이렇습니다.

> **노출은 점수에 들어가지 않습니다.** 점수가 이미 아는 것을 **증폭**하는 장치이고,
> 증폭이 일어나는 곳은 동적 시뮬레이션과 로그 생성기 두 군데뿐입니다.

| 자리 | 노출의 역할 | 점수에 영향 |
|---|---|---|
| 1. 점수 공식 | **없음.** 가중치 0 · 클릭률의 분모 | 없음 |
| 2. 오프라인 평가 (43.80%) | **개념 자체가 없음** | 없음 |
| 3. 동적 시뮬레이션 | 무엇을 보게 되는가를 정함 | **간접** (행동을 거쳐) |
| 4. 로그 생성기 | 같음 (`--exposure`) | **간접** (행동을 거쳐) |
| 5. 실제 서빙 화면 | 프론트가 `GET /api/recommend`(8300) 응답을 쓴다 (2026-09-11, MR !195). 서버 없으면 `recommendMock` 폴백 | 없음 (같은 items) |

## 1. 점수 공식 안에서는 아무 역할도 없습니다

```
score(u, i) = w₁ · cos(v_u, v_i)
            + w₂ · attr_affinity(u, i)
            + w₃ · prior(i)
            + w_b · brand_unknown(u, i)
            + β  · cf_bonus(u, i)        ← 2026-09-07 채택 (계약 §4-1)
```

**2026-09-07 부터 이 선형 합은 폴백입니다.** 정본은 **학습 결합**이고 위 항들은
모델의 피처로 들어갑니다 (계약 §4-2). **노출 항은 거기에도 없습니다** — 피처
19개 어디에도 "몇 번 보여줬나" 가 들어가지 않습니다.

노출 항이 없습니다. 행동 가중치에서도 **0** 입니다.

> **CF 를 얹어도 이 절의 답은 안 바뀝니다.** `cf_bonus` 의 입력은 **전환한 상품**
> 이지 노출된 상품이 아닙니다. 노출은 여전히 점수 공식 안에 들어오지 않습니다 —
> 다만 CF 가 붙으면서 **증폭할 값이 생겼습니다** ("그래서 노출로 정확도를
> 올릴 수 있는가" 절의 2026-09-07 재측정).

```ts
// frontend/src/types/log.ts:292
product_impression: 0,
recommendation_impression: 0,
impression_dwell: 0,
```

같은 파일의 주석이 이유입니다 — **"노출은 사용자 의지가 아니다. 가중 0 으로 두고
분모로만 쓴다."** 내가 고른 것이 아니라 시스템이 보여준 것이므로 취향의 증거가 될
수 없습니다. 다만 클릭률을 계산하려면 몇 번 보여줬는지가 필요하므로 **로그로는 남기고
분모로만** 씁니다.

취향은 `product_view` 1.0 을 기준선으로 그 위에서 셉니다.

> 행동 가중치의 단일 출처는 `frontend/src/types/log.ts` 이고, 배치는
> `batch/jobs/behavior_weights.py` 로 그 파일을 **직접 읽습니다.** 값을 복사해 두면
> 프론트가 바꿀 때 조용히 어긋납니다.

### 예외처럼 보이지만 아닌 것 — 서빙의 `view_cap`

`Recommender.rank()` 는 서빙에서 **이미 본 상품을 2개까지만** 목록에 남깁니다
(`VIEW_CAP = 2`). 이것은 노출이 점수를 바꾸는 것이 아니라 **같은 점수 위에서 목록을
거르는 것**입니다. 점수는 그대로고 순서만 바뀝니다.

오프라인 평가(`evaluation=True`)에서는 본 상품을 **전부** 뺍니다 — 누출 차단입니다.
**그래서 서빙 수치와 평가 수치를 나란히 놓으면 안 됩니다.**

## 2. 오프라인 평가에는 노출 개념이 없습니다

대표 지표 **Recall@10 = 43.80%** (holdout_a · CBF + CF + 학습 결합 20피처 · 2026-09-16; 09-10 의 19피처 모델은 42.15%) 는 이렇게 잽니다.

```
시드 벡터 -> 상품 200개 전부 점수 -> 상위 10개에 target 이 있나
```

화면도 탐색도 없습니다. 계산만 합니다. **그래서 노출 정책을 아무리 바꿔도 이 값은
움직이지 않습니다.** 노출 실험 결과를 대표 지표와 섞어 말하면 안 되는 이유입니다.

## 3. 동적 시뮬레이션 — 노출이 실제로 작동하는 곳

`batch/jobs/eval_dynamic.py` 가 6 step 의 탐색을 돌립니다.

```
후보 pool 12개 = 추천 top 6 + 같은 카테고리 인기 3 + 무작위 3
                                     (POOL_MIX, eval_dynamic.py:55)
        ↓
  exp(score × T) 확률로 하나를 뽑는다  ← 이것이 "노출".  T = 3 (현행)
        ↓
  본 상품에 대한 행동은 hidden preference 가 정한다  ← 추천이 정하지 않는다
        ↓
  그 행동이 v_u 를 갱신 → 다음 점수 → 다음 노출
```

**노출은 "무엇을 보게 되는가" 만 정합니다.** 무엇을 보고 어떻게 반응하는가는
`hidden_preference.py` 가 정합니다.

### 왜 노출과 행동을 떼어 놓았나

**추천이 행동까지 정하면, 추천이 만든 행동으로 추천을 평가하는 순환이 됩니다.**
"추천이 좋아서 담았다" 와 "담게 만들어 놓고 담았다고 센다" 가 구분되지 않습니다.

그래서 hidden preference 를 통제 장치로 둡니다 — 그 사람이 무엇을 좋아하는지는
추천과 **무관하게** 미리 정해져 있고, 추천은 그 사람 앞에 무엇을 놓을지만 정합니다.
추천이 잘하면 그 사람이 원래 좋아할 것을 앞에 놓게 되고, 그때 비로소 행동이 쌓입니다.

`target` 은 후보 pool 에 **강제로 넣지 않습니다.** 정답은 holdout 으로만 둡니다.

## 4. 로그 생성기 — `--exposure`

`simulator/generator/gen_behavior_logs.py` 가 PC 9,900명의 로그를 만들 때 무엇이
화면에 뜨는지를 고를 수 있습니다.

| 값 | 무엇 |
|---|---|
| `popular_v0` (기본) | 같은 카테고리 → 인기순. **전원이 같은 화면**을 본다 |
| `cbf_v1` | 추천 점수가 방문 후보의 **절반**을 정한다. 사람마다 다른 화면 |

여기서도 같은 분리가 유지됩니다 — 노출만 추천이 정하고 행동은 hidden preference 가
정합니다. 정책 이름을 `impression_dwell.algorithm` 에 실어 **로그를 사후에 구분**할
수 있게 해 두었습니다.

## 그래서 노출로 정확도를 올릴 수 있는가 — 없습니다 (2026-09-04 판정)

노출은 점수에 직접 들어가지 않으므로, 노출을 바꿔 정확도를 올리려면
**본 것 → 행동 → 벡터 → 다음 점수** 라는 우회로를 타야 합니다.

**그 경로 자체는 작동합니다.** 탐색 중 담은 상품이 정답과 닮은 사람은
Start 79.13% → Final 92.52%(+13.39%p)로 오릅니다.

그래서 "노출을 추천 점수 쪽으로 더 세게 기울이면 맞는 신호가 쌓인다" 를 가설로 두고
탐색 온도 `T` 를 다섯 단계로 바꿔 쟀습니다 (valid · 공통 부분집합 1,220명 · 같은 사람).

| 노출 정책 | Final | Δ (Start 5.41% 대비) | 담기 | 시드 브랜드 노출 |
|---|---:|---:|---:|---:|
| 무작위 (T=0) | 4.67% | −0.74%p | 1.9회 | 42.9% |
| **현행 (T=3)** | 3.77% | −1.64%p | 2.2회 | 62.4% |
| T=6 | 3.28% | −2.13%p | 2.3회 | 76.0% |
| T=12 | 3.44% | −1.97%p | 2.5회 | 84.8% |
| 점수 1등 고정 | 2.95% | −2.46%p | 2.5회 | 89.2% |

**다섯 조건 전부 Final < Start** 이고, 세게 걸수록 점추정이 오히려 나빠집니다.
현행 대비 짝지은 부트스트랩 2,000회에서 **구분되는 조건이 하나도 없습니다**
(전부 CI 가 0 을 포함). **가설을 기각합니다.**

### 왜 안 되나

노출을 세게 걸수록 시드 브랜드 노출이 42.9% → **89.2%** 로 오릅니다. 그런데
**정답이 시드 브랜드인 비율은 30.6%** 입니다. 점수를 더 믿을수록 한 브랜드로
좁아지고, 정답의 69.4%는 그 밖에 있습니다.

**노출은 점수가 이미 아는 것을 증폭할 뿐이고, 점수가 정답 쪽을 못 가리키면 증폭해도
소용이 없습니다.** 남은 원인은 노출이 아니라 점수 식 쪽 — 긍정 축이 여러 상품의
평균이 되며 무뎌지는 구조 — 입니다.

### ⚠ 2026-09-07 — **점수가 좋아지니 결론이 뒤집혔습니다**

위 문단이 조건을 이미 적어 두었습니다 — *"점수가 정답 쪽을 못 가리키면"*.
그때 점수는 CBF 였고, CBF 는 시드와 다른 브랜드의 정답을 **1.44%** 밖에 못
맞혔습니다. **CF 를 얹으면 그 값이 20~23% 가 됩니다. 증폭할 가치가 생겼습니다.**

같은 하네스에 CF 가점만 더해 다시 쟀습니다 (holdout_a · 공통 부분집합 1,076명 ·
사람별 고정 시드).

| 노출 정책 | Final | 현행 대비 | 시드 브랜드 노출 |
|---|---:|---|---:|
| 무작위 (T=0) | 6.69% | −0.93%p [−2.04, +0.19] · 0 포함 | 41.7% |
| **현행 (T=3)** | 7.62% | 기준 | 66.6% |
| T=6 | 7.25% | −0.37%p [−1.39, +0.65] · 0 포함 | 73.3% |
| **점수 1등 고정** | 7.62% | **+0.00%p [−0.93, +0.93] · 0 포함** | 78.1% |

**CBF 때 −2.46%p 였던 점수 1등 고정의 손해가 사라졌습니다.** 그뿐 아니라
**순서가 통째로 뒤집혔습니다** — CBF 에서는 무작위가 가장 나았는데 CF 에서는
무작위가 가장 나쁩니다.

**말할 때 지킬 것이 하나 늘었습니다.**

- **"노출 온도는 기각됐다" 를 조건 없이 말하면 안 됩니다.** 그것은 **CBF 기준**
  결론입니다. CF 가 붙으면 점수 쪽으로 기울여도 손해가 나지 않습니다
- 다만 **"점수순이 낫다" 는 근거도 없습니다** — 네 조건 전부 CI 가 0 을 포함해
  서로 구분되지 않습니다
- **브랜드 쏠림은 그대로입니다** (66.6% → 78.1%). 정확도가 안 나빠질 뿐, 화면이
  시드 브랜드로 채워지는 것은 변하지 않습니다. **교차 브랜드 유입률로 관리합니다**

### holdout_b 확인 (2026-09-07)

| 노출 정책 | holdout_a | holdout_b | 시드 브랜드 노출 (a/b) |
|---|---:|---:|---:|
| 무작위 (T=0) | −0.93%p · 0 포함 | −0.46%p · 0 포함 | 41.7 / 41.5% |
| **현행 (T=3)** | 기준 | 기준 | 66.6 / 66.0% |
| T=6 | −0.37%p · 0 포함 | −0.09%p · 0 포함 | 73.3 / 73.0% |
| **점수 1등 고정** | **+0.00%p** · 0 포함 | **−0.28%p** · 0 포함 | 78.1 / 76.7% |

**두 홀드아웃 모두 네 조건 전부 현행과 구분되지 않습니다.** 결론은 그대로입니다.

> **다만 "차이가 0" 이 아니라 "구분되지 않는다" 로 말해야 합니다.**
> holdout_a 의 `+0.00%p` 는 그 표본의 우연이고 holdout_b 에서는 −0.28%p 입니다.
> 점추정을 인용하면 안 되고, **CI 가 0 을 포함한다는 사실**만 말할 수 있습니다.
>
> CBF 때(부록 J) 점수 1등 고정이 **−2.46%p 로 CI 밖**이었던 것과 비교하면
> 크기가 한 자릿수 달라졌습니다. **그 변화는 실재합니다.**

> 재현: `Research/eval/eval_exposure_with_cf_20260907.py [--split holdout_b]`

### 곁들여 — 담기는 늘어납니다

노출을 점수 쪽으로 기울이면 담기가 1.9 → 2.5회로 늘어납니다. 9/2 노출 정책
실험(`popular_v0` 90건 → `cbf_v1` 108건)과 같은 방향입니다.

**담기가 느는 것과 정답을 맞히는 것은 별개입니다.** 담긴 것이 정답 쪽이 아니면
사용자 벡터만 흐려집니다. 노출 정책을 "전환이 늘었다" 로 팔면 안 됩니다.

> 재현: `Research/eval/eval_exposure_common_subset_20260904.py`
> 09-03 판(`eval_exposure_virtuous_cycle_20260903.py`)은 조건마다 표본이 갈려 있어
> 그 표를 그대로 인용하면 안 됩니다 — 자세한 것은

## 요약 — 말할 때 지킬 것

- **"노출" 이라고만 하지 말고 어느 자리인지 붙입니다** — 점수 / 오프라인 평가 /
  동적 시뮬레이션 / 생성기 / 실제 화면
- 노출 실험 결과를 **대표 지표 43.80% 와 섞지 않습니다.** 오프라인 축에는 노출이 없습니다
- **서빙 수치와 평가 수치를 나란히 놓지 않습니다** — 본 상품 처리가 다릅니다
  (서빙 2개까지 / 평가 전부 제외)
- 지금 **화면의 진열은 추천 결과가 아닙니다** (`skin_match_v0`)
- 노출 정책은 **담기를 늘리고 정확도는 못 올립니다.** 둘을 같이 말하지 않습니다 (화면 진열이 추천 결과가 된 지금도 이 결론은 같다)
- **"노출 온도 기각" 은 CBF 기준입니다** (2026-09-07). CF 를 얹으면 점수 쪽으로
  기울여도 손해가 없습니다. 조건을 빼고 인용하지 않습니다
