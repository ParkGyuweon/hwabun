# CBF 기술 검토서 — Cosine Similarity 계산 구조

> 2026-08-27 · 어휘집 버전 `0.3`
> 관련: [`recommendation-design.md`](recommendation-design.md) · [`recommendation-io-spec.md`](../../contracts/recommendation-io-spec.md) · [`product-feature-spec.md`](../../contracts/product-feature-spec.md)

## 1. 계산 구조

```
v_i  : 상품 벡터 (93차원, L2 정규화)
v_u  : 사용자 벡터 = 상호작용 상품 벡터의 행동 가중 평균 (93차원, L2 정규화)

cos(v_u, v_i) = v_u · v_i        (둘 다 정규화되어 있으므로 내적 = 코사인)
```

두 벡터를 모두 L2 정규화해 저장하므로 **서빙 시 나눗셈이 없습니다.** 내적 한 번이 코사인입니다.

```
scores = V @ v_u        # (200 x 93) @ (93,) -> (200,)
```

## 2. Product Vector `V` 검증

| 항목 | 값 |
|---|---|
| 형태 | `(200, 93)` `float32` |
| 메모리 | **73KB** |
| L2 노름 | 전 상품 min 1.000000 / max 1.000000 |

정규화가 전 상품에 정확히 적용됨을 확인했습니다.

### 2-1. 상품 간 코사인 분포 (39,800쌍)

| 분위 | 어휘집 `0.2` (72차원) | 어휘집 `0.3` (93차원) |
|---|---:|---:|
| **p50** | 0.0211 | **0.0658** |
| p95 | 0.6571 | 0.5969 |
| p100 | 1.0000 | 1.0000 |
| 0.99 이상 쌍 | 19쌍 | **1쌍** |

**중앙값이 0.07입니다.** 대부분의 상품 쌍이 거의 직교합니다. 원핫·멀티핫 기반이라 벡터가 희소하기 때문이며, 정상입니다.

성분 어휘를 30종으로 확장하면서 중앙값이 0.02 → 0.07로 올랐고, **동일 벡터 쌍이 19쌍에서 1쌍으로 줄었습니다.** 5장 참조.

### 2-2. 음수 코사인이 없습니다 — 설계상 중요

```
음수 쌍: 0개 / 39,800쌍 (0.00%)
```

모든 블록의 값이 0 이상(원핫 / 멀티핫 + IDF / 정규화 스칼라)이므로 **상품 벡터는 항상 1사분면**에 있습니다. 따라서 코사인이 `[0, 1]` 범위로 보장됩니다.

이 성질이 두 가지를 해결합니다.

1. **곱셈 결합이 안전합니다.** `cos × attr × prior` 형태를 쓸 때 부호가 뒤집히는 문제가 발생하지 않습니다. (컨설턴트 검토 항목이었던 사안)
2. **MMR 벌점이 안전합니다.** 중복 벌점 `max cos(i, 선택된 것)`이 항상 0 이상이므로 벌점이 보너스로 뒤바뀌지 않습니다.

> 단, **사용자 벡터는 음수 성분을 가질 수 있습니다** (저평점 리뷰의 음수 가중치). 따라서 `cos(v_u, v_i)`는 음수가 될 수 있습니다. 3-2절 참조.

## 3. User Vector `v_u` 검증

### 3-1. 생성식과 증분 갱신

```
v_u = Σ(w_k × decay(t_k) × v_i_k) / Σ|w_k × decay(t_k)|
```

분모에 **절대값**을 쓰는 것이 중요합니다. 음수 가중치가 섞였을 때 분모가 0에 가까워지거나 음수가 되는 것을 막습니다.

**증분 갱신이 전체 재계산과 일치하는지 검증했습니다.**

```
가중치 [+2.0, -2.0, +4.0, +1.0] 4개 상품
전체 재계산 vs 누적합 증분 갱신
→ 최대 절대오차 0.00e+00
```

`(u_sum, w_sum)`만 Redis에 보관하고 이벤트마다 더하는 방식이 수학적으로 동등합니다. 전체 재계산 없이 O(93)로 갱신 가능합니다.

### 3-2. 엣지 케이스 — 처리 규칙 미정 (미해결 1)

페르소나 2,000명을 실제로 인코딩해 가중치 패턴을 분류했습니다.

| 패턴 | 인원 | 비율 | 문제 |
|---|---:|---:|---|
| 전부 양수 | 1,294 | 64.7% | 정상 |
| 0 포함 | 383 | 19.1% | 평점 3점 리뷰는 기여 0 |
| 혼합 (양수+음수) | 287 | 14.3% | 정상 동작하나 노름 축소 |
| **전부 음수** | **36** | **1.8%** | 벡터가 본 상품의 **반대 방향** |
| **가중치 합 0** | **11** | **0.5%** | **0으로 나눔** |

> 어휘집 `0.3`(93차원)에서 재측정한 결과 1,000명 표본 기준 가중치 합 0이 **3명(0.3%)**, 전부 음수가 **11명(1.1%)** 으로 줄었습니다. 벡터가 풍부해져 상쇄 확률이 낮아진 결과이며, 처리 규칙은 여전히 필요합니다.

**(a) 가중치 합 0 — 반드시 처리해야 합니다**

리뷰가 모두 3점인 사용자입니다. 분모가 0이 되어 division by zero가 발생합니다.

> **권고:** `w_sum == 0`이면 `w1 = 0`으로 강제하고 속성 항과 인기도 항만 사용합니다. 코사인을 0으로 두는 것과 동일한 효과이며, 별도 분기 없이 스케줄로 흡수됩니다.

**(b) 전부 음수 — 정책 판단이 필요합니다**

본 상품 전부에 저평점을 준 사용자입니다. 벡터가 반대 방향을 향하므로 **본 상품과 비슷한 상품의 코사인이 음수**가 되어 순위가 내려갑니다.

개념적으로는 의도한 동작입니다("싫어한 것과 다른 걸 추천"). 다만 1.8%뿐이고, 코사인이 음수가 되면 곱셈 결합 시 부호 문제가 생깁니다.

> **권고안 2가지 중 선택 필요**
> - **A** — 그대로 사용. 가중합 방식이라면 음수 코사인이 자연스럽게 감점으로 작동
> - **B** — `cos = max(cos, 0)`으로 클리핑. 곱셈 결합을 택할 경우 필수

**(c) 노름이 작은 경우 — 방향이 불안정합니다**

```
어휘집 0.2 (72차원):  min 0.098 / 중앙 0.735
어휘집 0.3 (93차원):  min 0.243 / 중앙 0.638
```

양수와 음수 가중치가 거의 상쇄되면 노름이 떨어집니다. 이 상태에서 L2 정규화하면 **작은 잔차가 증폭되어 방향이 노이즈에 지배**됩니다.

성분 어휘 확장으로 최소 노름이 0.098 → **0.243** 으로 올라 위험이 상당히 줄었습니다. 다만 임계값 처리는 여전히 권고합니다.

> **권고:** 정규화 전 노름이 임계값(예: 0.15) 미만이면 `w1`을 한 단계 낮춥니다. 신뢰할 수 없는 방향에 큰 가중치를 주지 않기 위함입니다.

**(d) 평점 3점 리뷰는 기여가 0입니다**

```
평점 3점 리뷰: 604 / 7,280 (8.3%)
```

`(rating − 3) × 2` 이므로 3점은 가중치 0입니다. 의도된 설계(중립)이지만, **전체 리뷰의 8.3%가 사용자 벡터에 전혀 반영되지 않는다**는 점은 인지해야 합니다.

다만 `seen` 집합에는 포함되므로 **추천 후보에서는 제외**됩니다. 이 부분은 일관적입니다.

## 4. 블록 가중치 조정 — 카테고리 비중 하향

### 4-1. 문제

기존 가중치에서 **상위 5개 추천의 카테고리 종류가 평균 1.90개**였습니다. 페르소나 절반 가까이가 한 종류만 받았습니다.

행동이 쌓여도 개선되지 않았습니다.

| 상호작용 상품 수 | `w1` | **본** 상품 카테고리 종류 | **추천** top5 카테고리 종류 |
|---|---:|---:|---:|
| 2개 | 0.35 | 1.82개 | 2.20개 |
| 3~5개 | 0.60 | 2.87개 | 1.70개 |
| 6~9개 | 0.80 | 4.82개 | 1.73개 |
| 10개+ | 0.80 | **6.96개** | **1.71개** |

상품 10개 이상 본 사용자는 카테고리 7종을 둘러봤는데 추천은 1.71종만 받습니다.

### 4-2. 원인은 `w1`이 아니라 콘텐츠 벡터 내부

`w1`을 낮추면 행동 기반 추천 자체가 약해집니다. 문제는 **코사인 유사도가 카테고리에 지배되고 있다**는 점이었습니다. 카테고리 두 블록의 실효 비중이 39%였습니다.

### 4-3. 측정 — 페르소나 1,000명

카테고리 블록만 낮추고 `w1` 스케줄은 유지한 결과입니다.

| 시나리오 | 카테고리 실효비중 | top5 카테고리 종류 | top5 평균 코사인 | concern 겹침률 |
|---|---:|---:|---:|---:|
| 기존 | 39.0% | 1.90개 | 0.614 | 77.6% |
| −25% | 30.6% | 2.40개 | 0.607 | 82.7% |
| −45% | 24.0% | 2.79개 | 0.616 | 85.3% |
| **−60% (채택)** | **17.0%** | **3.13개** | **0.632** | **86.7%** |
| 위 + 성분 어휘 30종 (`0.3`) | 17.0% | **3.21개** | 0.580 | **88.0%** |
| 카테고리 제거 | 0% | 3.63개 | 0.649 | 86.2% |

**다양성을 올렸는데 관련성이 함께 올라갔습니다.**

```
다양성        1.90 → 3.13개  (+65%)
평균 코사인   0.614 → 0.632  (상승)
concern 겹침  77.6% → 86.7%  (상승)
```

카테고리 원핫이 유사도를 독점하고 있었기 때문입니다. 비중을 낮추자 `concern`(피부 고민)과 `ingredient`(성분)가 제 역할을 시작했고, **"같은 종류의 제품"이 아니라 "같은 고민을 해결하는 제품"** 이 추천됩니다.

카테고리를 완전히 제거하는 안은 채택하지 않았습니다. 다양성은 더 높지만 무관한 제품군까지 올라올 위험이 있습니다.

### 4-4. 확정 가중치

| 블록 | 이전 | **확정** |
|---|---:|---:|
| `concern` | 0.29 | **0.42** |
| `ingredient` | 0.18 | **0.27** |
| `tertiary_category` | 0.24 | **0.11** |
| `secondary_category` | 0.15 | **0.06** |
| `clean` | 0.06 | 0.06 |
| `price_bin` | 0.04 | 0.04 |
| `rating` | 0.02 | 0.02 |
| `texture` | 0.02 | 0.02 |

어휘집 `0.3`에서도 이 가중치는 그대로 유지됩니다. 변경된 것은 `ingredient` 블록의 차원(9 → 30)과 값 산출 방식입니다.

### 4-5. MMR 재검토 결과 — 지금은 손대지 않습니다

카테고리 비중을 낮추기 전에는 MMR `λ=0.7`이 무력했습니다(다양성 개선 0). 그러나 그것은 **근본 원인을 두고 증상만 누르려던 것**이었습니다.

가중치 조정으로 다양성이 3.13개까지 올라왔으므로 MMR 파라미터는 실제 로그의 지표(클릭률·카테고리 커버리지)로 판단하는 것이 맞습니다. **현행 `λ=0.7` 유지, 후보 풀 제한은 미적용.**

> 참고로 MMR을 전체 200개에서 `λ=0.5`로 돌리면 원점수 0.023짜리 무관한 상품까지 올라옵니다. 조정할 때는 **점수 상위 30개 후보 풀로 제한**하는 표준 방식을 함께 적용해야 합니다.

## 5. 서로 구분되지 않는 상품 — 해소 (31개 → 4개)

### 5-1. 현상

어휘집 `0.2`(72차원)에서 **코사인 1.0000인 상품 쌍이 19쌍** 있었습니다.

```
1.0000  The True Cream Aqua Bomb  |  The True Cream Moisturizing Bomb
1.0000  The True Cream Aqua Bomb  |  Greek Yoghurt Nourishing Gel-Cream
1.0000  The True Cream Aqua Bomb  |  Original Skin Matte Moisturizer
```

서로 다른 브랜드의 다른 제품인데 벡터가 완전히 동일했습니다.

### 5-2. 원인

`concern`과 `ingredient` 블록이 **둘 다 비어 있는 상품이 31개(15.5%)** 였습니다. 이 두 블록이 확정 가중치에서 **69%** 를 차지하므로, 비어 있으면 남는 것은 카테고리(17%) + 가격(4%) + 평점(2%) + `clean`(6%)뿐입니다. 같은 `tertiary_category`, 같은 `price_bin`, 비슷한 `rating`이면 벡터가 사실상 같아집니다.

근본 원인은 `highlights`가 **세포라 마케팅 태그**라는 점입니다. 필수 필드가 아니라 상품마다 있고 없습니다.

### 5-3. 해결 — 전성분 파싱 + 어휘 확장

`highlights`는 비어도 **`ingredients`(전성분)는 200/200 채워져 있습니다.**

```
highlights:  []
ingredients: ["Water, Glycerin, Sodium Hyaluronate, Niacinamide, ..."]
```

동의어 패턴으로 전성분에서 성분을 복원합니다. 태그가 붙은 성분의 **91.5%** 를 재발견하고, 태그에 없던 **159건**을 새로 찾았습니다.

**어휘를 9종 → 30종으로 확장했습니다.** 상위 200개 중 **5~120개 상품 보유** 구간만 채택했습니다.

| 채택 | 제외 |

### 5-6. 알려진 한계 — 카테고리 혼입 (미보정)

`lift`는 **전체 리뷰를 기준선**으로 계산합니다. 따라서 세그먼트의 **카테고리 선호가 일부 섞여 있습니다.**

카테고리별 `oily` 비중을 보면 효과가 확인됩니다.

| 카테고리 | `oily` 비중 |
|---|---:|
| Blemish & Acne Treatments | 16.6% |
| Toners | 15.3% |
| Face Wash & Cleansers | 13.8% |
| **(전체 평균)** | **12.3%** |
| Eye Creams & Treatments | 10.9% |

지성 사용자는 원래 토너·클렌저를 많이 쓰고 아이크림은 덜 씁니다. 따라서 토너 제품의 `oily` lift에는 제품 고유 특성과 카테고리 효과가 섞입니다.

**Balancing Force Oil Control Toner** (`Toners`)로 확인한 결과입니다.

| 세그먼트 | 상품 비중 | 전체 기준선 | 카테고리 기준선 | 전체기준 lift | 카테기준 lift |
|---|---:|---:|---:|---:|---:|
| `oily` | 32.5% | 12.3% | **15.3%** | 2.56 | **2.08** |
| `dry` | 6.7% | 19.2% | 17.0% | 0.38 | 0.42 |
| `combination` | 55.5% | 55.3% | 56.1% | 1.00 | 0.99 |

lift 2.56이 실제로는 2.08 수준으로 과대평가되어 있습니다. **다만 방향과 순위는 유지됩니다.**

전체 200개 상품으로 두 기준선을 비교한 결과입니다.

| 세그먼트 | 전체기준 lift 표준편차 | 카테기준 lift 표준편차 | 상관 | 편차 감소 |
|---|---:|---:|---:|---:|
| `combination` | 0.053 | 0.051 | 0.927 | 4.7% |
| `dry` | 0.238 | 0.223 | 0.947 | 6.1% |
| `normal` | 0.158 | 0.136 | 0.873 | **14.1%** |
| `oily` | 0.289 | 0.276 | 0.945 | 4.4% |

**상관 0.87~0.95, 편차 감소 4~14%.** lift의 대부분은 카테고리가 아니라 제품 고유 특성에서 나옵니다. `normal`만 14.1%로 큰데, "자극 없는 중간 제품 선호"가 카테고리 수준에서 나타나기 때문으로 보입니다.

**미보정 유지 결정 근거 3가지**

1. **표본 분할** — `tertiary_category` 19종 × 세그먼트 20종 = 380개 기준선을 추정해야 합니다. `Face Wipes`·`Eye Masks`는 상품이 1개뿐이라 기준선이 그 상품 자신이 되어 lift가 항상 1.00이 됩니다
2. **카테고리 효과 제거가 항상 옳지 않음** — "지성 사용자에게 토너를 추천한다"는 것 자체가 유효한 신호입니다. 콘텐츠 벡터에 카테고리 블록이 별도로 있으므로, 친화도 항에서는 전체 기준이 자연스럽습니다
3. **영향이 4~6%** — 얻는 것보다 표본 부족·해석 복잡도 손실이 큽니다

> 참고: `lift`는 연관규칙 마이닝의 표준 지표이며, 마케팅에서는 `Index`, 역학에서는 `O/E ratio`, NLP에서는 `PMI`(로그 형태), 생물정보학에서는 `enrichment`로 불립니다. 기준선을 무엇으로 잡을지는 분야마다 다르고, 본 프로젝트는 전체 기준을 택했습니다.

## 8. 결론

**CBF 계산 구조는 확정 가능합니다.** 코사인 계산·증분 갱신·성능이 모두 검증되었고, 값 범위가 `[0, 1]`로 보장되어 결합 방식 선택의 제약이 없습니다.

**착수 전 결정이 필요한 항목 2개**

1. **사용자 벡터 엣지 케이스 처리 규칙** (3-2절) — `w_sum == 0`(0.5%)은 반드시 처리해야 하며, 음수 벡터(1.8%)와 작은 노름(min 0.098)은 정책 선택이 필요합니다
2. ~~`concern`+`ingredient` 빈 상품 31개 보완~~ → **해소.** 성분 어휘 30종 확장 + 전성분 파싱으로 4개까지 감소 (5장)

**로그 생성 이후로 미루는 항목**

- MMR `λ` 및 후보 풀 (4-5절)
- 시간 감쇠 `τ = 30일`
- `hair_color` / `eye_color`의 **가중치 재조정** (존치는 확정, 0.10 유지)
