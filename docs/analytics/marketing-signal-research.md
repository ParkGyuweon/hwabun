## 1. 먼저 알아야 할 것: 정확한 가중치는 공개되지 않는다

조사에서 가장 중요한 결론이다. **네이버쇼핑·무신사·올리브영 모두 랭킹에 쓰는
지표 "목록"은 공개하지만, 각 지표의 가중치·집계 기간·정규화 방식은 공개하지 않는다.**

- 네이버는 적합도/인기도/신뢰도 3축과 그 하위 항목까지 공개하지만 비중은 비공개
- 무신사는 매출·판매수량·조회수·후기수를 쓴다고 밝히고 공식은 비공개.
  기술 블로그도 집계 스택(Databricks/Spark, Elasticsearch, 90ms 응답)까지만 공개
- 올리브영은 산정 기준 자체를 공식 문서로 공개하지 않는다

따라서 "업체들이 쓰는 비율"을 그대로 베껴올 수는 없다. 대신 쓸 수 있는 것은:

| 근거 종류 | 신뢰도 | 이 문서 표기 |
|---|---|---|
| 플랫폼·도구 공식 문서에 명시된 것 | 높음 | **[공개]** |
| 업계에서 표준처럼 쓰이는 관행·논문 기법 | 중간 | **[관행]** |
| 위 둘에서 우리 프로젝트용으로 유추한 것 | 낮음 | **[추정]** |

**[추정] 항목은 우리가 정한 값이라는 뜻이다.** 문서나 발표에 인용할 때
플랫폼이 그렇게 한다고 쓰면 안 된다.

## 2. 무엇을 수집하나 — 커머스 표준 수집 항목

### 2-1. GA4 이커머스 권장 이벤트 [공개]

GA4 는 이커머스 권장 이벤트 11종을 정의하고, 그중 일부를 퍼널 단계로 인식한다.
최소 구성은 `view_item` → `add_to_cart` → `begin_checkout` → `purchase` 4종이다.

| 단계 | 이벤트 | 우리 페이지에 있나 |
|---|---|---|
| 상품 열람 | `view_item` | O |
| 목록 노출 | `view_item_list` | X (목록 페이지 없음) |
| 목록 클릭 | `select_item` | X |
| 찜 | `add_to_wishlist` | O (좋아요) |
| 장바구니 | `add_to_cart` | O |
| 장바구니 열람 | `view_cart` | X |
| 장바구니 제거 | `remove_from_cart` | X |
| 결제 시작 | `begin_checkout` | X (범위 밖) |
| 배송정보 입력 | `add_shipping_info` | X |
| 결제정보 입력 | `add_payment_info` | X |
| 구매 | `purchase` | X (범위 밖) |

우리 프로젝트는 **구매 이전 탐색 구간만** 다루므로 퍼널 뒷부분이 비어 있다.
표준 이벤트만으로는 신호가 너무 적어서 탐색 구간을 촘촘히 봐야 한다.
이게 우리가 주목·좌절 신호를 따로 만든 이유다.

### 2-2. 표준 이벤트가 덮지 못하는 탐색 구간 [관행]

행동 분석 도구들이 공통으로 재는 참여 지표는 다음과 같다.

| 항목 | 무엇을 재나 |
|---|---|
| 체류 시간 | 페이지·섹션에 머문 시간 |
| 스크롤 깊이 | 어디까지 내려갔나 (보통 25/50/75/100%) |
| 섹션 노출 | 어떤 블록이 화면에 들어왔나 |
| 이미지·미디어 열람 | 갤러리 전환, 확대 |
| 옵션 상호작용 | 색·용량 전환 횟수와 왕복 |
| 아코디언·탭 펼침 | 어떤 정보를 일부러 찾아봤나 |
| 텍스트 선택·복사 | 어떤 문구에 반응했나 |
| 재방문·재조회 | 같은 상품을 다시 봤나 |

GA4 는 참여 여부를 **engaged session** 으로 요약한다 [공개].
세션이 **10초 초과**, 또는 **key event 1건 이상**, 또는 **페이지뷰 2건 이상**
중 **하나만 만족하면** 참여 세션으로 센다. 10초 임계값은 설정으로 바꿀 수 있다.

여기서 배울 점은 임계값 자체보다 **여러 조건의 OR 구조**다.
단일 신호로 참여를 판정하지 않는다.

## 3. 어떤 신호로 해석하나 — 항목별 의미와 강도

수집 항목을 그대로 쓰지 않고 **의도(intent)** 로 번역해서 쓴다.
같은 클릭도 무엇을 눌렀는지에 따라 뜻이 다르다.

| 수집 항목 | 해석되는 신호 | 방향 | 강도 | 근거 |
|---|---|---|---|---|
| 구매 | 확정된 선호 | + | 최상 | [공개] 모든 플랫폼이 최상위로 씀 |
| 장바구니 담기 | 구매 의도. 구매로 안 이어져도 관심 신호 | + | 상 | [관행] 논문에 명시 |
| 찜·좋아요 | 지속적 관심. 즉시 구매는 아님 | + | 상 | [공개] 네이버 인기도 항목 |
| 후기 작성 | 구매 후 참여. 상품 신뢰도 근거 | + | 상 | [공개] 무신사 랭킹 항목 |
| 상품 조회 | 최소 관심. 양이 많아 노이즈도 많음 | + | 하 | [공개] 네이버·무신사 공통 |
| 클릭수 | 노출 대비 선택. 제목·이미지 매력도 | + | 중 | [공개] 네이버 인기도 항목 |
| 체류 시간 | 관심의 깊이 | + | 중 | [관행] |
| 스크롤 깊이 | 정보를 실제로 읽었나 | + | 중 | [관행] |
| 옵션 왕복 | 결정 못 함. 관심 높지만 **마찰** 동반 | ± | 중 | [추정] 화장품 특유 |
| 성분·상세 펼침 | 능동적 검증. 신중한 구매자 | + | 중상 | [추정] 화장품 특유 |
| 리뷰 열람 | 결정이 아니라 **확인** 단계 | + | 중 | [추정] |
| 빠른 이탈 | 부적합 | − | 중 | [관행] |
| 같은 곳 반복 스크롤 | 원하는 정보를 못 찾음 (좌절) | − | 중 | [추정] |

### 핵심: 암묵 신호는 하나만 보면 안 된다

체류 시간이 길다는 게 관심일 수도 있고 자리를 비운 것일 수도 있다.
그래서 실무에서는 **여러 신호를 조합**한다. GA4 의 engaged session 이 OR 조건인 것,
추천 시스템이 confidence 행렬을 쓰는 것이 같은 이유다.

## 4. 얼마큼 반영하나 — 세 가지 계열의 반영 방식

"비율"은 목적에 따라 완전히 다르게 정해진다. 세 계열을 섞어 보면 안 된다.

| 계열 | 목적 | 반영 방식 | 대표 |
|---|---|---|---|
| A. 랭킹형 | 상품 순위 정하기 | 지표별 점수 합산 후 정렬 | 네이버쇼핑, 무신사, 올리브영 |
| B. 추천형 | 개인별 취향 예측 | 행동을 선호도 점수로 환산해 모델 학습 | 협업 필터링, 우리 CBF |
| C. 세그먼트형 | 고객 분류·마케팅 실행 | 축별 점수화 후 등급 나누기 | RFM, 대시보드 도구 |

### 4-1. 랭킹형 — 3축 구조 [공개]

네이버쇼핑이 구조를 가장 명확히 공개했다.

| 축 | 하위 항목 | 성격 |
|---|---|---|
| **적합도** | 필드 연관도, 카테고리 선호도 (상품명·카테고리·브랜드 기입 정확도) | 정적. 판매자가 관리 |
| **인기도** | 클릭수, 판매실적, 구매평 수, 찜 수, 최신성, 배송유형·정보 | 동적. 행동 신호 |
| **신뢰도** | 쇼핑 페널티, 상품명 SEO 준수 | 감점 요소 |

배울 점 두 가지:

1. **행동 신호(인기도)는 3축 중 하나일 뿐이다.** 상품 정보 품질(적합도)과
   패널티(신뢰도)가 같은 급으로 들어간다. 행동만으로 순위를 만들지 않는다.
2. **신뢰도는 가점이 아니라 감점 축이다.** 어뷰징을 거르는 자리다.
   무신사에서 일부 입점사가 순위를 조작한 사례가 보도된 만큼 실제로 필요한 축이다.

### 4-2. 추천형 — 암묵 피드백 가중치 [관행]

명시적 별점이 없을 때 행동을 선호도 점수로 환산한다.
`view=1, cart=3, purchase=5` 같은 방식이 흔히 쓰이지만 **표준으로 고정된 값은 아니다.**
전처리 단계에서 정의하는 설계 변수다.

| 기법 | 내용 |
|---|---|
| pseudo-rating | 행동 종류·횟수를 점수로 환산해 별점처럼 씀 |
| confidence 행렬 (Hu et al., Pan et al.) | 관측된 행동에 높은 신뢰도, 미관측에 낮은 신뢰도를 부여 |
| 인기도 인식 가중 | 균일 가중보다 인기도를 고려한 가중이 성능이 좋다는 결과 |

주의할 점 [관행]:

- **균일 가중은 좋지 않다.** 조회처럼 양이 많은 신호가 결과를 지배한다
- **롱테일 편향**이 생긴다. 인기 상품이 계속 추천되는 쪽으로 쏠린다

### 4-3. 세그먼트형 — RFM [관행]

| 축 | 의미 |
|---|---|
| Recency | 최근성 — 관계의 온도 |
| Frequency | 빈도 — 습관의 깊이 |
| Monetary | 금액 — 가치의 크기 |

각 축을 1~5점으로 매겨 조합한다 (최대 125 세그먼트). 축별 가중치는 업체가 정한다.

RFM 은 **구매 이력 기반**이라 구매 데이터가 없는 우리 프로젝트에는 그대로 쓸 수 없다.
다만 "축을 나눠 점수화하고 등급으로 묶는다"는 구조는 참고할 수 있다.

## 5. 플랫폼별 상세

### 5-1. 네이버쇼핑

| 구분 | 내용 | 근거 |
|---|---|---|
| 공개 구조 | 적합도 / 인기도 / 신뢰도 3축 | [공개] |
| 인기도 항목 | 클릭수, 판매실적, 구매평 수, 찜 수, 최신성, 배송유형·정보 | [공개] |
| 적합도 항목 | 필드 연관도, 카테고리 선호도 | [공개] |
| 신뢰도 항목 | 쇼핑 페널티, 상품명 SEO | [공개] |
| 모델 | AI·머신러닝 기반으로 랭킹 요소 추출. 트리 기반 모델 도입 발표 | [공개] |
| 가중치·집계 기간 | **비공개** | — |

특징: **최신성**이 인기도에 들어간다. 신규 상품에 노출 기회를 주는 장치이면서,
동시에 행동 데이터가 시간 감쇠된다는 뜻이기도 하다 [추정].

### 5-2. 무신사

| 구분 | 내용 | 근거 |
|---|---|---|
| 상품 랭킹 지표 | 상품 매출, 판매 수량, 상품 조회 수, 작성 후기 수 | [공개] |
| 브랜드 랭킹 지표 | 인지도, 매출, 상품 조회 수 | [공개] |
| 추천순 | 클릭·좋아요 등 인터랙션을 고려 | [공개] |
| 광고 반영 | **없음.** 100% 순위만 집계 | [공개] |
| 갱신 주기 | 실시간 / 일간 / 주간 / 월간 / 3개월 | [공개] |
| 집계 스택 | Databricks·Spark 집계, Kotlin Spring Boot + Elasticsearch, 90ms 응답 | [공개] |
| 공식·가중치 | **비공개** | — |

특징:

- **기간별 랭킹을 따로 제공한다.** 같은 신호를 집계 창만 바꿔 여러 랭킹을 만든다
- **광고를 랭킹에서 분리한다.** 신뢰가 랭킹의 자산이라는 판단
- 리스크: 랭킹이 매출에 직결되므로 **순위 조작 시도가 실제로 발생**했다 (보도)

### 5-3. 올리브영

| 구분 | 내용 | 근거 |
|---|---|---|
| 랭킹 산정 기준 | **공식 공개 없음** | — |
| 확인되는 것 | 구매 데이터가 핵심. 2024 어워즈 선정에 약 1.6억 건 구매 데이터 활용 | [공개] |
| 업계 관찰 | 판매량이 검색 순위에 영향. 체험단으로 초기 구매를 만들어 순위를 올리고 그 노출로 오가닉 매출을 얻는 운영이 존재 | [관행] |

시사점: 구매량 가중이 크면 **초기 구매를 인위적으로 만드는 어뷰징**이 생긴다.
네이버가 신뢰도 축을 별도로 둔 이유와 같은 문제다.

## 6. 화장품 고유 신호

일반 커머스 신호에 더해, 화장품은 **개인 적합성**이 구매 판단을 지배한다.

| 신호 | 왜 화장품에서 중요한가 | 근거 |
|---|---|---|
| 피부 타입·고민 | 개인의 피부 특성·민감도에 따라 선호가 명확히 갈린다 | [공개] 논문 |
| 성분 확인 | 적합성 검증 수단. 능동적 탐색 행동 | [추정] |
| 색·향·용량 옵션 왕복 | 실물을 못 보므로 옵션 사이를 오간다 | [추정] |
| 리뷰의 속성 정보 | "내 피부와 비슷한 사람" 후기를 찾는다 | [관행] |
| 스와치·상세 이미지 | 색·질감을 이미지로 대체 판단 | [추정] |

연구 결과 [공개]: 검색 기록만 쓰는 기존 협업 필터링보다,
**피부 타입·고민 같은 콘텍스트 정보를 함께 넣은 모델이 성능이 더 좋다.**

우리 데이터셋의 `suitable_skin_types`, `skincare_concerns`, 성분 필드가
행동 로그와 함께 쓰일 때 값이 커진다는 근거다. 실제로 AI 파트가 성분 어휘를
확장하고 전성분 파싱 기반 인코딩을 넣은 방향과 일치한다.

## 7. 우리 이벤트 목록과의 차이

### 7-1. 조사로 뒷받침되는 것

| 우리 설계 | 조사 근거 |
|---|---|
| 클릭 외 암묵 신호(체류·스크롤·노출)를 함께 남긴다 | GA4 engaged session 이 OR 조건 [공개] |
| 이벤트에 `intent` / `content_kind` 속성을 붙인다 | 같은 클릭도 대상에 따라 의미가 다름 [관행] |
| 옵션 왕복을 별도 신호로 본다 | 화장품 개인 적합성 [공개 논문] |
| 성분 펼침을 능동 검증으로 본다 | 피부 특성 기반 선호 [공개 논문] |
| 암묵 신호를 단독으로 쓰지 않는다 | confidence 행렬, OR 조건 [관행] |

### 7-2. 보완이 필요한 것

| 항목 | 조사에서 나온 시사점 | 필요한 작업 |
|---|---|---|
| **감쇠·집계 기간이 없다** | 네이버는 최신성, 무신사는 기간별 랭킹을 둔다 | 신호의 시간 창·감쇠 정의 |
| **어뷰징·신뢰도 축이 없다** | 네이버 신뢰도, 올리브영 체험단 사례 | 비정상 로그 판별 기준 (합성 트래픽 `actor_type` 과 별개) |
| **조회 신호 지배 위험** | 균일 가중은 양 많은 신호가 결과를 지배 | 조회 대비 저빈도 고강도 신호에 가중 |
| **목록 단계 신호가 없다** | GA4 `view_item_list` / `select_item` | 목록 페이지 구현 시 노출·클릭 로그 |
| **가중치가 문서화되지 않았다** | 어떤 플랫폼도 남의 가중치를 쓰지 않는다 | 우리 값으로 정하고 **[추정]** 으로 명시 |

### 7-3. 우리 프로젝트용 초기 가중치 제안 [추정]

**아래 숫자는 어떤 플랫폼의 값도 아니다.** 조사한 강도 순서를 우리 상황
(구매 데이터 없음, 탐색 구간만 있음)에 맞춰 배치한 출발점이다.
데이터를 보고 조정해야 하며, 인용할 때 반드시 추정임을 밝혀야 한다.

| 신호 | 제안 가중 | 이유 |
|---|---|---|
| 장바구니 담기 | 5 | 구매가 없는 환경에서 가장 강한 의도 신호 |
| 좋아요·찜 | 4 | 지속 관심. 저빈도 |
| 옵션 선택 완료 | 3 | 특정 옵션까지 좁혔다 |
| 성분·상세 펼침 | 3 | 능동적 검증 |
| 리뷰 열람 | 2 | 확인 단계 |
| 이미지 갤러리 전환 | 2 | 화장품에서 이미지 비중이 큼 |
| 섹션 체류(임계 초과) | 2 | 단독으로는 약함. 조합해서 씀 |
| 상품 조회 | 1 | 양이 많아 기준선 역할 |
| 좌절 신호(반복 스크롤 등) | −2 | 감점 |
| 빠른 이탈 | −2 | 감점 |

원칙 세 가지:

1. **조회를 1 로 두고 나머지를 상대적으로 잡는다** — 조회가 기준선
2. **감점 축을 둔다** — 네이버 신뢰도 구조를 축소해 반영
3. **단독 판정 금지** — 체류·스크롤은 다른 신호와 함께일 때만 의미를 준다
